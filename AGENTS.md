# AGENTS.md — Alfred Hexapod Lab

> Инструкции для AI-агентов, работающих с репозиторием `Dmitry-dev-pet/alfred-hexapod-lab`.
> Приоритет: собственная интерактивная вычислительная среда агента, воспроизводимость, GitHub как источник истины. 
> Действует для всех экспериментов с симуляцией Freenove FNK0052, MuJoCo, геометрией, управлением и рендерингом.

## 1. Где выполнять работу

**По умолчанию — непосредственно в доступной вычислительной среде агента в текущем сеансе.** Сначала проверь, какие реальные возможности среды доступны, затем выполняй расчёты, симуляции, тесты, рендер MP4/GIF/PNG и анализ результатов *там же*. Не отправляй каждую итерацию в GitHub Actions и не запускай для неё отдельный runner.

- Среда может быть временной и меняться между сеансами. **Не утверждай**, что Python, MuJoCo, Xvfb, FFmpeg, FreeCAD или пакеты установлены, пока не проверишь это в текущей среде.
- Если нужной библиотеки нет, сначала используй штатные инструменты установки в среде. Для MuJoCo предусмотрен офлайн-бандл на Google Drive: `Alfred-Runtime-Bundles/MuJoCo-3.14.0-cp313-linux-x64`. Проверь совместимость ОС/архитектуры/Python, хеши и лицензию, прежде чем устанавливать.
- Публичные исходные CAD-активы загружай по закреплённой ревизии через `data/fnk0052_cad_assets_lock.json` с проверкой Git blob SHA; сохраняй в локальном игнорируемом кэше, а не в Git.
- Если непосредственное исполнение невозможно, честно укажи точный блокер и что *не* удалось проверить. GitHub Actions разрешается применить как **осознанный запасной вариант** для воспроизводимой проверки, но не как основной рабочий движок и не по умолчанию.

- Для видео/анимаций по умолчанию готовь **оба формата MP4 и GIF**, если это полезно для просмотра, и используй ракурс, на котором видны движущиеся ноги, точки контакта и весь робот. Желательно проверять хотя бы кадры до/после переноса. Видео и GIF должны воспроизводить физическую симуляцию, а не изображать вымышленную динамику.

## 3. GitHub Actions = CI, а не ежедневная среда моделирования

Используй Actions только когда есть конкретная причина: независимая контрольная проверка на чистой машине, проверки PR/регрессии, совместимости окружений или воспроизводимости, либо явно согласованная необходимость fallback.

**Не создавай workflow и не запускай Actions только для того, чтобы увидеть новую позу, поменять ракурс, просчитать шаг или получить GIF/MP4**, когда задача выполнима в текущей среде. Не запускай Actions через малые правки коммитов ради каждого эксперимента. Существующие автоматические PR-проверки допустимы как CI, но не должны быть обязательным шагом исследовательской итерации.

Если CI нужен, сначала добейся локального результата, затем сохрани входные параметры, версии зависимостей, seed (если есть), исходный Git commit, критерии успеха/неуспеха и числовые результаты. GitHub Actions должен **проверять**, а не подменять исследование.

## 4. Научная корректность физической модели

- Мы работаем с **Freenove Big Hexapod FNK0052**. Результаты `v0.3` относятся к упрощённой диагностической модели; `v0.4` использует оригинальную CAD-геометрию по открытому источнику, но массы, инерции, привод и контакт ещё требуют проверки на реальном оборудовании.
- Различай **наблюдённое в симуляции**, **рассчитанную оценку**, **данные производителя** и **измеренное на настоящем роботе**. Не называй модель откалиброванным цифровым двойником без проверки.
- Сохраняй массу по сценариям, измеримые контакты всех шести ног, наклоны/положение корпуса, пределы моментов, фазу шага и ошибки IK. Не выдавай перестановку одной стопы за поступательное движение корпуса.
- Не предполагай тождество именования left/right в CAD и Freenove: проверяй таблицу `docs/FREENOVE_MOTOR_MAP.md` по номерам 18 каналов. Сопоставление `MuJoCo qpos -> заводской PWM` пока **не откалибровано**.
- Не копируй закрытые или неразрешённые 3D-файлы из сторонних источников. Используй реестр ссылок, происхождения и контрольных сумм.

## 5. GitHub workflow и границы изменений

- Основные источники истины: README, `docs/PHYSICAL_MODEL_V04.md`, `data/`, `results/`, Issues и PR проекта.
- Ветка текущей реконструкции: `research/v04-physical-reconstruction`, черновой PR #4. **Не сливай в `main` без явного одобрения пользователя.**
- Новые кодовые решения проверяй тестами; фиксируй отрицательные результаты и причины. Если эксперимент не запускался, не говори «проверено».
- Не предлагай писать в поддержку Freenove: для текущей реконструкции использовать открытый STEP/URDF/MJCF и независимые технические источники; предпочтение пользователя — без обращения в поддержку.

**Короткое правило:** считай и рисуй здесь → сохраняй MP4/GIF и большие данные в Drive → фиксируй воспроизводимый код/результаты в GitHub → используй Actions только для контрольного CI.
