# Hexapod Lab — заводской режим Freenove Original V7

Дата: 6 ноября 2026. Проект FNK0052 / CAD30, issue #64. Публикуется **новой записью в существующем плеере Android**, без изменения прежних опытов, без слияния PR и без фонового MuJoCo.

## Что действительно происходит

Алгоритм готовит офлайн настоящие углы суставов CAD30 из заводского алгоритма 5Freenove Big Hexapod Robot Kit for Raspberry PiB, [Code/Server/control.py](https://github.com/Freenove/Freenove_Big_Hexapod_Robot_Kit_for_Raspberry_Pi/blob/b7d228cc870b0a802d3768bfcf742f85fa8695f6/Code/Server/control.py). Используются инкременты `run_gait` без вызовов PWM и `sleep`. Оригинальные режимы `gait=1` (tripod) и `gait=2` (wave), исходные диапазоны `CMD_MOVE` X/Y ±35 мм, Z=40 мм; `CMD_POSITION` X/Y ±40 мм, Z ±20 мм; `CMD_ATTITUDE` roll/pitch/yaw ±15°. Для поворота (OEM параметр angle не ограничен этим методом) **профиль интерфейса выбран ±10°** — не выдавать за предел производителя.

OEM команда X/Y ±35 мм *не равна* нашей прежней длине полного переноса: у заводского tripod в нормальном фазовом цикле полная амплитуда стопы 70 мм, у wave — приблизительно 58,3 мм. В браузере `Темп` регулирует частоту исполнения; заводские кадровые структуры для этой версии рассчитаны офлайн по реальным F=48 (tripod, speed=8) и F=108 (wave, speed=6). Походка Ripple *отсутствует у оригинального контроллера*; она остаётся в нашем отдельном экспериментальном V5.

## Адаптация системы координат

Производитель задаёт абсолютные планарные точки стоп `[(137.1,189.4),(225,0),(137.1,-189.4),(-137.1,-189.4),(-225,0),(-137.1,189.4)]` мм; для CAD30 из моторной карты установлен `CAD_X=-VENDOR_X; CAD_Y=VENDOR_Y`. Левый и правый суффиксы имён CAD относительно производителя *зеркальны*. Вместо прямого копирования OEM PWM, `scripts/build_factory_v7.py` пересчитывает 18 углов CAD30 с помощью полной модели и SciPy IK; две оси головы остаются в CAD-нейтрали.

В заводском коде нет координаты абсолютной высоты корня MuJoCo CAD30. **Согласованная по геометрии исходная стойка в нашем CAD30 поставлена на +15 мм выше прежней V4**; это адаптер, а не измеренная реальная заводская высота. Поднятые и опорные стопы сверяются по исходным точкам. По результату CAD-совместимости предшествующий лимит `|q|≤1.7 rad` не годится для штатного полного Z=40; для **только визуального** IK-расчёта использован `|q|≤2.4 rad` (механические range модели шире, реальные servo end-stops / physical PWM **не определены**). *Не использовать эти 2.4 рад для моторов.*

## Исполнение на планшете

Приложение **не вычисляет динамику и не применяет обратную кинематику** во время движения. Оно загружает заранее рассчитанные для 2 походок циклы по 48 поз × 11 командных направлений (`forward/back/left/right`, диагонали, cw/ccw, lift-only), плавно смешивает 18 суставных поз по джойстику, выполняет обычный FK для 27 CAD-узлов. `CMD_POSITION` и `CMD_ATTITUDE` представлены как шесть пар крайних заранее рассчитанных поз, джойстик X/Y перемещает корпус, ползунки отвечают за высоту, крен, тангаж и yaw. Для совместных движений допускается интерполяция в пространстве суставов, **не гарантированная как точная декартова поза**. Измеренные силы, реальные контакты и моменты двигателей отсутствуют, карта перемещения корпуса — лишь командное предсказание.

Используются уже установленные `/hexapod/player-shell.css/.js`, `live-v2-offline/pilot.css`, проверенные локальные 30 STL и `data/cad-rig-live-v1-slow.json`, базовый V4 `live-v4-gaits-kit.json` только как **опорный 3D-скелет**. Новые файлы размещаются в `/hexapod/freenove-original-v7/` и `data/freenove-original-v7-kit.json`; библиотека обновляется кнопкой по проверенным SHA256 и размерам.

## Что проверено, а что нет

- Полный OEM native incremental gait создаётся на базе реальных F, включая диагонали и повороты; 2 × 11 × 48 = **1056 поз из 20 углов** (2 головных нейтральных), 6 ног.
- Максимальная локальная ошибка CAD30 IK в готовых таблицах <0,27 мм, ниже заданного 0,8 мм. Все рассчитанные 6×3 суставов укладываются в *визуальный* CAD-IK лимит ±2,4 рад, **не** в старый ±1,7 рад.
- 6 заводских одноосевых поз корпуса, положительные/отрицательные крайние положения: X/Y ±40 мм, Z ±20 мм, roll/pitch/yaw ±15°. Проверка поз по шести реально вычисленным кончикам ног, сохраняющим мировую точку.
- Для целевой конечной среды проверить локальные файлы, запуск через браузерный `/api/refresh`, управление пальцем и FPS на Samsung Tab S7. Автоматические JS/Python тесты — только кодовые и геометрические тесты.
- **Не доказано:** динамическая стабильность, удержание и реальная сила контакта, отсутствие всех самостолкновений, моменты сервоприводов, заводские реальные угловые нули/знаки, отклик при одновременном full move+turn/body sliders, реальная скорость ходьбы. Физическое поведение требует отдельного офлайн полного MuJoCo-исследования, без real-time физики.

**V5** остаётся для отдельного управления одной ногой/головой. **V6 Issue #64 / PR #65** остаются исследованием достижимости. Не закрывать и не переименовывать эти задачи. Без разрешения владельца не сливать в `main`.
