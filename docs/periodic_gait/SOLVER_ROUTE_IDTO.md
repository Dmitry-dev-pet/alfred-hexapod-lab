# CAD30 / P0 — переход к готовой численной оптимизации траекторий

Дата: 2026-11-05. Решение владельца: использовать стандартную задачу оптимального управления вместо ручной подстройки отдельных статических поз/следующих ног. Основная Issue **#50**; протокол критериев — [PROTOCOL.md](PROTOCOL.md). Это **план переноса решателя**, не свидетельство работающей походки.

## Почему именно IDTO/Drake

- В PR #33 уже нативно воспроизведён **Toyota Research Institute IDTO** на Mini Cheetah: pinned upstream `de0629c7811aa9b330e56c4385629005b09495f0`, Drake 1.30.0, 10 с реального closed-loop MPC, C++/Linux amd64. Исходные бинарники и зависимости — в личном Drive, сборка вне Docker; GitHub Actions использовались лишь для транспорта зависимостей, не физики.
- IDTO — готовая *contact-implicit* оптимизация обратной динамики: может выбирать контактные события без заданной вручную фазы и работать как MPC. Однако **не гарантирует** минимум 3 настоящих контакта, заданную медленную походку, периодичность или достижимость PID/PD-приводом Freenove. Глобальный оптимум также не гарантируется.
- Альтернатива при неудаче IDTO: **Drake multiple shooting / direct collocation с явно заданными фазами** и условиями контакта, либо иная существующая NLP-библиотека. Не реализовывать новый интегратор/контактный оптимизатор с нуля.
- **MuJoCo CAD30 остаётся независимым физическим проверяющим**. Нельзя объявлять решением воспроизведение Drake-сценария или анимацию без настоящих контактов.

Источники: https://github.com/ToyotaResearchInstitute/idto (контактно-неявный solver); https://idto.github.io/ ; https://drake.mit.edu/doxygen_cxx/group__multibody__parsing.html (MJCF parsing caveats).

## Проверенные ограничения метода (до переноса на CAD30)

В сохранённом Drive `idto-contact-mode-sweep-summary-20261104.json` пять **действительно выполненных** контрольных прогонов Mini Cheetah с одинаковыми моделями и изменённым только `q_nom_end.x`, контакты посчитаны каждые 50 мс за 10 с, порог `Fz>0.2N`:

| goal q_nom_end.x | real dx | отсчётов с 4/3/2 нагруженными ногами | заключение |
|---|---:|---:|---|
| 0.10 м | +0.047403 м | 201/0/0 | почти статическая стойка; шаги не доказаны |
| 0.15 м | +0.058053 м | 201/0/0 | почти статическая стойка; шаги не доказаны |
| 0.18 м | +1.135978 м | 60/98/43 | есть движение, 3-support требование нарушено |

| 0.40 м | +3.466846 м | 1/29/171 | быстрый trot, не наша четырёхногая crawl |

**Отбор по 50мс не доказывает непрерывные контакты.** Ни один из пяти прогонов не доказывает четырёхшаговую медленную походку с минимум тремя опорами на каждом такте. Это исключает «снизим скорость Mini Cheetah — и всё готово».

## Практический контракт реализации

### A. Drake CAD30 bridge (G0; обязательный before optimization)

1. Исходное реальное состояние `qpos/qvel/ctrl` из архива Freenove CAD30 / PR #40, original 30 STL только в личном Drive. Использовать именно сохранённый 6-support baseline, не произвольную идеальную IK-позу.
2. Проверить сначала **прямой импорт MJCF в Drake Parser**. Поддержка MJCF частичная: возможны игнорируемые MuJoCo атрибуты `solref/solimp`, контакты/трение и сервоприводы отличаются. При необходимости строить *эквивалентную* Drake SDF/URDF-модель; не считать простой парсинг подтверждением эквивалентной физики.
3. Для двух одинаковых тестовых поз (реальная шестиопорная и реальная четырёхопорная): `nq/nv/nu`, имена и направления всех 18 осей, mass/COM/inertia, 6 toe world XYZ, геометрия IK/Jacobians, гравитационные обобщённые силы, Fz/моментные бюджеты. Зафиксировать расхождения, причины и пределы допуска до оптимизации. **Если не совпадает модель — NO_GO, не ретюнить solver.**

### B. Полный контактно-неявный период (G1)

1. От выбранной физической шестиопорной позы оптимизировать **подготовку 6→4 + повторяемый четырёхшаговый период** по полному состоянию корпуса и 18 приводов. Условия из [PROTOCOL.md](PROTOCOL.md): `q(T)=q(0)`, `v(T)=v(0)`, одинаковая ориентация/контактный режим, каждая из `ml/mr/bl/br` имеет verified liftoff→clearance→touchdown, концевые стопы сдвинуты на такой же `ΔY`, как корпус. По завершении периода `ΔY≥20мм`.
2. Первый прогон IDTO **без изменения алгоритма** — выявить, может ли при соответствующей целевой функции сам найти допустимый цикл. Если выбранный режим контактов не отвечает ≥3 опорам, это **FAIL**, а не «почти работает». Не скрывать нарушений мягким штрафом.
3. Если IDTO не допускает нужных жёстких ограничений на контакт/период, **сразу** перейти к фазовому multiple shooting/direct collocation в Drake с явно ограниченными контактами/комплементарностью и четырьмя swing-фазами; документировать, какие ограничения введены. Это другой solver route, а не «настроенный IDTO PASS».
4. Поиск с разными seeds/инициализациями и ограниченным бюджетом. Сохранить целевые функции, все уравнения, контактные residuals, угловые/моментные ограничения и серии FAIL. Для `NOT_FOUND_WITHIN_BOUNDS` указать диапазон, не заявлять физическую невозможность.
5. Для исходного физического Freenove позиции приводов важнее оптимальной `tau(t)`: переводить найденные `tau` в допустимые **позиционные PD-цели**, сравнивать фактически реализуемые моменты, насыщения и скорости. Если torque trajectory невыполнима позиционными сервами — `ACTUATOR_REALIZATION_FAIL`.

### C. Независимый G2 в MuJoCo

Запустить ***в одном непрерывном free-base MjData*** исходную шестиногую позу → подготовку → не менее трёх полных периодов через действительно доступные командные входы ног. Без записи root `qpos`, сбросов и ручного редактирования контактов между фазами. Каждые 2 мс измерить `Fz` каждой tibia, true contact pairs, slip, COM support, clearance, body pose/orientation, `q,qd,τ`, ошибки PD; проверить все лимиты PR #53. При реальном контакте менее трёх необходимых опор или незамкнутом периоде — FAIL. Раздельно: `ΔY_cycle`, `ΔY_prep`, `netY_from_original_six`; целевой суммарный net after 3 cycles ≥20мм. Только после него G3 robustness.

## Конкретный ближайший исполнимый этап

**Реализовать и запустить только G0 — model parity / actuator parity**, а не очередную локальную коррекцию `bl/br`. Выдать минимальный репродуцируемый Python/C++ harness и JSON `cad30_drake_mujo_co_parity.json` с числом dofs, именами осей, массами, COM, гравитационными моментами, toe frames, валидностью PD/torque интерфейса. Статус `PARITY_PASS | PARITY_FAIL | NOT_RUN`. Следующий PR только после реального запуска/тестирования мостика; никаких фиктивных результатных графиков.

Хранение: GitHub = source, тесты, конфиги, компактные receipts + SHA256. Приватные Freenove CAD/STL и большие физические трассы — только личный Google Drive. Не запускать физику на GitHub Actions, не управлять настоящим роботом, не менять `main` и не merge без разрешения.
