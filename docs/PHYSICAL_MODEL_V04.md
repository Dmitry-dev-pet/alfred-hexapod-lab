# v0.4 — восстановление реальной физической модели Freenove FNK0052

**Статус:** начата реконструкция; **не** откалиброванный цифровой двойник. Исследовательский трек: [Issue #3](https://github.com/Dmitry-dev-pet/alfred-hexapod-lab/issues/3). Контроллеры походки сравнивать на физической модели после прохождения ворот ниже.

## Зачем это нужно

Модель v0.3 является диагностическим наброском MuJoCo с 18 DOF. Известны эффективные длины звеньев из кода производителя, но положения осей, массы каждого сервопривода и батарей, инерции, распределение масс, корпуса, сервоприводы головы и силовая электроника смоделированы условно или не смоделированы. Её геометрическая масса составляет **1.402 кг по предположениям**, **не реальная масса FNK0052**. Нельзя подгонять недостающие массы к неподтверждённому числу «2 кг», встречающемуся в сторонних карточках.

## Машиночитаемое происхождение

Реестр [`data/fnk0052_v04_manifest.json`](../data/fnk0052_v04_manifest.json) содержит: `source` для каждого подтверждённого параметра, статус `documented_in_vendor_control_code` или `unverified`, единицы, область применимости, перечень масс с `mass_each_kg: null`, а также явные ворота достоверности. Для значений `unverified` записан `null`, **не ноль**.

Ссылки на первоисточники зафиксированы в JSON; `control.py` привязан к commit `b7d228cc870b0a802d3768bfcf742f85fa8695f6` производителя. Контрольная копия кода Freenove здесь не публикуется.

### Что подтверждает код, а что ещё нет

| Данные | Статус | Примечание |
| --- | --- | --- |
| l1/l2/l3 = 33/90/110 мм | Подтверждено кодом | **Кинематические** эффективные длины; не CAD-длина каждой детали |
| `body_points`, шесть начальных координат стоп | Подтверждено кодом | `z=-25` — настройка контрольной системы, не заводской замер высоты |
| `body_structure` 55/76 и 85 мм | Подтверждено кодом | Точки расчёта позы, пока **не** доказано, что это точные центры осей |
| Повороты локальных систем ног 54, 0, −54, −126, 180, 126° | Подтверждено кодом | Не является полной 3D-моделью установки сервоприводов |
| 18 серв ног и 2 серв головы | Подтверждено списком производителя | Точные SKU, массы, максимальные моменты — ещё нет |
| 2 держателя + требуются 4 × 18650 | Подтверждено списком/магазином | Аккумуляторы отсутствуют в комплекте и зависят от выбора |
| Материалы, контуры и толщина пластин | Не подтверждены численно | Изображения сборки дают форму, но не допуски и чертёж |
| Оси каждого реального шарнира, центры масс, тензоры инерции | Не подтверждены | Пока не использовать для строгой валидации походки |

Руководство сборки отдельно предупреждает о разной ориентации сервоприводов левой и правой сторон.

## Рабочие процедуры v0.4

1. **Геометрия, без масс.** По руководству сборки восстановить корпус и шесть цепей из жёстких тел; найти STEP/DXF производителя либо параметризовать силуэты с проверяемыми масштабами. Разделить фактическую точку шарнира и условные `body_structure`/радиальные смещения в скрипте.
2. **Знаки осей и kinematics.** Должны воспроизводиться `coordinate_to_angle` и `angle_to_coordinate` производителя для набора достижимых поз. Не путать угол серво из PWM с суставным углом: для левых и правых ног разные преобразования.
3. **Ведомость масс.** Для каждого тела измерить или установить по datasheet отдельную массу (кг), точку приложения и источник; отличать серво от механики того же звена; учесть 4 реальных 18650, 2 батарейных отсека, электронику и головную часть.
4. **Инерции.** Для однородных CAD-тел рассчитывать геометрическую инерцию из материалов; для сервоприводов и сложных сборок получать приближение с погрешностью или измерять. Пересчитывать в COM каждого звена по теореме Штейнера, сохранять тензоры и проверки собственных значений.
5. **Две конфигурации.** Эталон с Raspberry Pi и проектируемая ESP32-версия. Смена контроллера меняет массу, крепление и питание. Оставлять неизменную электронику/голову лишь как проектное допущение.
6. **Динамика и калибровка.** Контакты, трение, диапазоны движения, кривые момент–скорость/питание сервоприводов калибруются отдельно. Номинальный stall torque нельзя считать постоянным рабочим моментом.
7. **Реальное измерение** после появления аппарата: взвешивание целиком и по модулям, размеры осей, видео походки, ток/напряжение, угол, положение IMU, контактные события.

## Ворота физического исследования

- Нет входа в научные сравнения контроллеров, пока `ready_for_physics_comparison` возвращает `False`.
- Полнота перечня масс — обязательная, но не достаточная предпосылка. Нужны позы, реальные оси, инерции, характеристики приводов и проверка по физическому роботу.
- Ни численный результат v0.3, ни поставщик с массо-габаритной цифрой без определения комплектации не становятся «измерением» по умолчанию.
- В каждом будущем отчёте указывать версию GitHub commit, ревизию манифеста, допуски/источники и версию конфигурации.

## Проверка реестра

```bash
python -m hexlab.physical_v04
python -m unittest discover -s tests -v
```

Первая команда должна показать `mass_budget_complete: false`, `total_mass_kg: null`, `ready_for_physics_comparison: false`. Это **правильное** состояние на этапе сбора фактов, а не неисправность симулятора.

### Наиболее важная следующая информация

1. STEP/DXF и спецификация механических деталей оригинального FNK0052: можно запросить у `support@freenove.com` с указанием цели — simulation/CAD.
2. Фактическая модель и масса сервоприводов в конкретном экземпляре; не переносить сведения о MG996R из стороннего *самодельного* гексапода без доказательства.
3. Масса / плотность / толщина и точки соединения акриловых пластин, кронштейнов, головного узла, проводки и крепежа.
4. Масса выбранных четырёх аккумуляторов и выбранного вычислителя — Pi или ESP32. Только после определения комплектации имеет смысл сводить общую массу.

Пока эти данные отсутствуют, любые 3D-модели следует помечать **reconstructed / uncertain**, а не **manufacturer exact**.
