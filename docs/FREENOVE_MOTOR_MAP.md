# FNK0052 — соответствие CAD-суставов и каналов штатного контроллера

Дата: 2026-11-03 · статус: **проверено на уровне названий суставов, не калибровано на железе**.

Первый запуск эксперимента одиночного шага был правильно остановлен: пометка `fr` у CAD не равна штатной `FR` из `Freenove/Code/Server/control.py`. При прямом сопоставлении по именам `motor{channel}` обнаружена зеркальная перестановка левых/правых обозначений. **Ошибочное переименование без проверки физического положения недопустимо.**

| По схеме Freenove | Ветка CAD/MuJoCo | Каналы (coxa, femur, tibia) |
| --- | --- | --- |
| FR — передняя правая | `fl` | 15, 14, 13 |
| MR — средняя правая | `ml` | 12, 11, 10 |
| RR — задняя правая | `bl` | 9, 8, 31 |
| LR — задняя левая | `br` | 22, 23, 27 |
| ML — средняя левая | `mr` | 19, 20, 21 |
| FL — передняя левая | `fr` | 16, 17, 18 |

Факты для автоматической проверки:

- Freenove: [`control.py` на закреплённой ревизии](https://github.com/Freenove/Freenove_Big_Hexapod_Robot_Kit_for_Raspberry_Pi/blob/b7d228cc870b0a802d3768bfcf742f85fa8695f6/Code/Server/control.py), функции `set_leg_angles` и `coordinate_to_angle`.
- CAD/MJCF: [Mattia Grigoli, PR #1](https://github.com/MattiaGrigoli/autonomous_hexapod/pull/1), исходный commit `5c9a84c16335b30036e451c691d2c544abf4bc72`.
- Реестр и защита от повторной ошибки: [`hexlab/freenove_servo_map_v04.py`](../hexlab/freenove_servo_map_v04.py), [тесты](../tests/test_freenove_servo_map_v04.py).
- Первое моделируемое действие на штатной передней правой ноге (`FR`, каналы 15/14/13) должно выбирать **CAD-ветку `fl`**, а не `fr`. Это выбор по каналам; физическую лево/право ориентацию камерой/маркировкой подтвердить при проверке настоящего робота.

## Углы — ещё не сопоставлены

У Freenove функция `set_leg_angles` применяет:

- Для штатных FR/MR/RR: yaw = a+calA; femur = 90-(b+calB); tibia = c+calC.
- Для штатных LR/ML/FL: yaw = a+calA; femur = 90+b+calB; tibia = 180-(c+calC).
- Команды приводов ограничиваются диапазоном 0–180°.

`a,b,c` здесь **углы обратной кинематики производителя**, а не напрямую `qpos` MuJoCo. Неизвестны механическая нулевая позиция, знаки всех 18 суставов относительно моторного энкодера (если бы он был), люфты, заводская калибровка и фактические ограничители. Даже идеальная геометрическая симуляция не подтверждает, что можно отправлять углы PWM от полученной модели реальному роботу.

**До оборудования:** проверять названия и номера каналов на исходных файлах, рассматривать команды в диапазонах и с защитой от столкновений; не выводить команды для железа из `qpos` автоматически. **После покупки:** индивидуальная калибровка безопасным движением одного сервопривода за раз без нагрузки и тесты направлений до первого шага.
