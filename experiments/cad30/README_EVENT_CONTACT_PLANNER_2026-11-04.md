# Событийный математический планировщик контактов CAD30 — без MPC

**Статус:** 4 ноября 2026, исследовательский прототип на MuJoCo 3.14.0 (Python 3.13), **не** эксперимент на физическом Freenove и **не** доказательство глобально оптимальной походки. База — `research/optimized-claw-support-gait-20261104` (PR #18), математический эталон из PR #16. GitHub Actions не использовались для вычисления.

## Что алгоритм выбирает сам

Нет расписания tripod/wave и централизованного заранее заданного порядка ног. Каждая нога имеет *явно запрограммированный* опорный цикл и сенсор контакта. При готовности к переносу математический планировщик перебирает подмножества из **одной или двух** готовых ног. Для каждой альтернативы используется состояние **реальной CAD30 физики** (положение центра масс, контактные точки, гравитация, реакции, якобианы суставов). LP решает уравнения равновесия и минимизирует максимальную долю доступного момента привода, QP находит распределение нормальных реакций с меньшим разбросом.

Ограничения: сумма контактных сил равна весу, сумма моментов равна нулю, вертикальная сила каждой контактной ноги неотрицательна, трение соответствует вписанному 32-гранному конусу, суставные моменты в условных пределах. Набор допустим к подъёму при рассчитанном запасе многоугольника **≥10 мм** и минимальной загрузке приводов **≤82%**. Это фильтр *текущей* квазистатической возможности, не гарантия безопасности всего динамического шага.

Из двух доступных ИК-примитивов точки постановки (20/35 мм) выбирается достижимый по суставам вариант с учётом запаса момента и приблизительного многоугольника после приземления. Во всех отложенных прогонах μ=1.1 был выбран 35-мм вариант. **Непрерывной оптимизации координат стоп пока нет.** Решение об очередном подъёме принимается по событиям/контактам, а не по глобальной временной фазе. При физическом движении PD-моменты ограничены ±0.7 Н·м (только модельное допущение).

Дополнительный вариант **force-feedback** отслеживает рассчитанные QP цели нормальных сил, подправляя высоту стопы в пределах ±1.8 мм, не быстрее 8 мм/с. Уравнение поддерживаемого вертикального равновесия *не* обеспечивает точную силу в динамике: это ограниченное позиционное приближение, которое измеряется отдельно.

## Завершённое парное сравнение

Три заранее выбранных вне разработки начальных состояния **101, 133, 197**, μ=1.1, 8 секунд физики каждое, одинаковые массы/трение/ИК/скорости, по одному прогону без силового регулятора и с ним.

| Seed | Только выбор опор, см | +силовая обратная связь, см | MAE Fz без → с (Н) | Мин. фактические опоры без → с |
|---:|---:|---:|---:|---:|
| 101 | 10.0287 | 11.9676 | 1.0087 → 0.3433 | 2 → 3 |
| 133 | 11.8103 | 11.8553 | 0.9384 → 0.5633 | 3 → 3 |
| 197 | 10.2238 | 11.2017 | 1.0251 → 0.6734 | 2 → 2 |
| **Среднее** | **10.6876** | **11.6749** | **0.9907 → 0.5267** | — |

Продвижение увеличилось на **9.24%**, средняя абсолютная ошибка отслеживания целевой силы снизилась на **46.84%**. Доля физических **2-мс** шагов с менее чем тремя контактами снизилась с **0.475% до 0.108%**, но не исчезла. **В seed=197 остаются две опоры и отрицательный геометрический запас центра масс**. В некоторых отсчётах 50-Гц диагностики отрицательный COM-margin наблюдался в обеих группах. Все шесть 8-секундных прогонов завершены без порогового падения и насыщения приводов. Выборка n=3 слишком мала для обобщения.

При μ=0.6 завершён отдельный контроль без силы (seed=101: 12.5466 см; минимум 2 опоры), **парная серия с силовой коррекцией не завершена** и в основное сравнение не включена. Никаких выводов об устойчивости на скользком покрытии.

## Чего алгоритм пока не умеет

* **Подъём двух физически передних «клешней» из невыгодной позы:** текущий фильтр может отказать, хотя в PR #18 уже проверен отдельный предварительный перенос COM. Его надо включить в события «подготовить COM → подтвердить 4 опоры → поднять обе → приземлить → вернуть COM».
* Без гарантии будущего касания и всей последовательности восстановления; статический LP/QP не является MPC или нелинейным оптимизатором всего движения.
* Без калибровки реальных сервоприводов, массы деталей, стоп, трения, инерционной обратной связи, задержки и шума датчиков. Это централизованный математический планировщик, не биологическая локальная нейросеть.

## Воспроизведение

Восстановить исходный приватный CAD30 ZIP с `source/` и `hexlab/` из [Drive](https://drive.google.com/file/d/1qN8KAgekhXm5RasMXSHNxHAsMxivpZ44/view?usp=drivesdk), совместить с кодом PR #18 и новым `event_contact_planner.py`:

```bash
PYTHONPATH=.:experiments/cad30 python -m unittest discover -s experiments/cad30/tests -v
PYTHONPATH=.:experiments/cad30 python experiments/cad30/event_contact_planner.py --seed 101 --mu 1.1 --seconds 8 --out results/holdout_base.json
PYTHONPATH=.:experiments/cad30 python experiments/cad30/event_contact_planner.py --seed 101 --mu 1.1 --seconds 8 --force-feedback --out results/holdout_force.json
python experiments/cad30/finalize_event_contact.py
```

Последний скрипт требует исходные шесть JSON `heldout_seed*_mu1p1_force*.json`; для просмотра MP4/GIF сделаны отдельные кадры из сохранённых настоящих qpos (опция `--save-frames`). Тесты: **10 новых + 6 существующих = 16 пройдено** локально. Полные трассы и медиа в приватном Drive, GitHub хранит код, краткую сводку и SHA-256. Сторонние Freenove STL в новый архив/GitHub не включены.

**Следующая гипотеза:** расширить класс действий событием предварительного переноса COM для пары передних ног, плюс устранить динамические провалы COM-margin, прежде чем называть походку устойчивой или «всегда оптимальной».
