# CAD30 G1 — оптимизация *всего* четырёхшагового цикла в TRI IDTO

**Дата:** 2026-11-05  
**Статус:** `G1_FULL_PERIOD_NOT_FOUND / 4_SWING_KINEMATIC_CANDIDATE / MUJOCO_REPLAY_FAIL`  
**Главная задача:** [Issue #50](https://github.com/Dmitry-dev-pet/alfred-hexapod-lab/issues/50). Математический протокол: draft PR #53. Исходный real-MuJoCo контроллер: draft PR #49–#52. IDTO/Drake 1.30 уже воспроизводился в draft PR #33. Контактный мостик с исходными tibia mesh и конечным полом: draft PR #57–#60.

**Это не работающая походка.** Мы прекратили попытки калибровать совпадение всех контактных сил Drake/MuJoCo и впервые выполнили численный поиск целого четырёхшагового периода. Сравнили несколько длительностей и модельную жёсткость contact-smoothing; затем физически воспроизвели лучший расчёт в MuJoCo. `main` не изменён, реальный робот не управлялся.

## Исполненный эксперимент

- Исходная Freenove FNK0052 CAD30: 30 настоящих mesh в приватном Google Drive; 27 позиций, 26 скоростей, 20 приводов, масса ~1.8048682 кг, две передние ноги подняты. Pinned TRI IDTO commit `de0629c7811aa9b330e56c4385629005b09495f0`, Drake 1.30, MuJoCo 3.14.
- `generate_reference.py` переиспользует [PR #43](https://github.com/Dmitry-dev-pet/alfred-hexapod-lab/pull/43): исходный **математический** план из 218 узлов, узлы `106..217` после виртуальной подготовки, 29 выборочных конфигураций, 4 фазы `ML→MR→BL→BR` и номинальное смещение всех стоп/корпуса +20 мм. **Этот старт ещё не достигнут физически из первоначальных 6 опор.**
- `patch_local_idto.py` сохраняет оригинальный исходный `examples/example_base.cc` перед модификацией, добавляет опциональную time-varying номинальную последовательность (CSV), отдельный CSV для warm-start и экспорт найденных `q,v,τ`. Алгоритм TRI IDTO остаётся прежним. Патч и C++ цель пересобраны clang; старые проблемы линковки `gflags` устранены восстановлением пути к существующей офлайн-библиотеке, без Docker/GitHub Actions.
- Один **полный 29-узловой** цикл оптимизировали шестью вариантами, все IDTO выходы сохранялись. Один вариант `equality_constraints=true` использует предыдущее решение как начальное приближение (не изменение `q_nom`). Все достигли `MAX_ITERATIONS_REACHED`, сходимость не доказана.
- `evaluate_trajectory.py`: независимый **геометрический** экран на оригинальном MuJoCo CAD30 через `mj_forward`, включая реальные положения tibia collision meshes, max gap в каждой swing-фазе, точку стопы (объективный CAD mesh vertex), периодичность суставов/скоростей и явные пики `τ` из оптимизатора. Это **не** forward dynamics, там нет фактического Fz.
- `physical_replay_from_virtual_start.py`: два настоящих непрерывных free-base MuJoCo прогона длительностью 25.2 с, 12,600 тактов `dt=0.002`, исходное qpos записано только **до** начала физики. 18 двигателей получают PD `Kp=7/Kd=.32` с модельным ±0.7 Н·м; во втором прогоне дополнительно передаётся `τ` IDTO как feed-forward (piecewise constant на каждом оптимизационном интервале). Глобальная поза не фиксируется и не телепортируется.

|---|---:|---|---:|---:|---:|
| 80 итераций | 2.8 с | σ=10мм, k=2000Н/м | 3.259 Н·м | 0.886 | 19.755 мм |
| 70 итераций | 8.4 с | σ=10мм, k=2000Н/м | 2.291 Н·м | 0.297 | 19.864 мм |
| 70 итераций | 8.4 с | σ=2мм, k=3000Н/м | 0.769 Н·м | 0.299 | 19.977 мм |
| 70 итераций | 14.0 с | σ=2мм, k=3000Н/м | **0.677 Н·м** | 0.179 | 19.950 мм |
| 60 итераций | 25.2 с | σ=2мм, k=3000Н/м | **0.672 Н·м** | **0.098** | 19.883 мм |
| 35 итераций, unactuated equality=true | 25.2 с | σ=2мм, k=3000Н/м | 0.752 Н·м | 0.097 | 19.774 мм |

Исследовательские предварительные лимиты: |τ_leg| ≤0.7 Н·м, |τ_head| ≤0.2 Н·м, |q_leg| ≤1.7 рад, `max |v_end-v_start|≤0.1` в соответствующих смешанных единицах обобщённых скоростей, требуемое ΔY ≥20мм. **Все шесть вариантов отвергнуты строгим глобальным экраном**, в том числе из-за ΔY менее 20мм; некоторые также по моментам и скоростям. Уравнения неуправляемой динамики при `equality_constraints=false` штрафуются, но не обязаны быть точно нулевыми. При `equality_constraints=true` остаточная величина на тесте всё ещё 1.852 в смешанных единицах обобщённых сил/моментов, потому что оптимизатор остановился по лимиту итераций.

Лучший soft-вариант (25.2 с) **геометрически** переставляет каждую из ML/MR/BL/BR примерно на 19.7–20 мм вперёд; максимальные зазоры в соответствующих промежуточных фазах 9.6–11.1мм. Остальные рабочие стопы при дискретной проверке удерживаются около пола. Это **не гарантия физических трёх опор**: IDTO использует сглаженные контактные силы, а исходный старт — виртуальная IK/LP поза, не физически достигнутая подготовка.

## Независимая физика — один цикл, НЕ путь из шести ног

| MuJoCo, старт из *виртуальной* 4-опорной конфигурации | PD по углам | PD + feed-forward τ IDTO |
|---|---:|---:|
| Физический world-Y корпуса за 25.2 с | **−1.825 мм** | **+7.211 мм** |
| Минимум реальных нагруженных ног | 2 | 2 |
| Первый срыв нужной тройки в swing ML | 4.862 с | 3.598 с |
| Шагов с насыщением моторов | 0 | **500** |
| В конце 0.4 с четыре ноги нагружены | 100% | 100% |
| Динамически подтверждённый период | **FAIL** | **FAIL** |

В PD+feed-forward эксперименте у `BR` пропала реакция, пока `ML` переносилась; требуемого непрерывного трёхопорного контакта нет, моторы насыщались. **Положительные +7.2 мм не являются полной gait.** Оба прогона **не включают физически проверенный 6→4 переход**, и не воспроизводят три периода. No reset/teleport *после инициализации* не означает физически доказанную достижимость старта.

## Что делать дальше

Не продолжать бесконечно подбор отдельной ноги, не возвращаться к требованию полного совпадения контактных сил двух движков. Вместо обычной мягкой стоимости IDTO следующий шаг — использовать **готовый фазовый direct collocation / multiple shooting solver** с явным: 4 swing contact schedule, твёрдый минимум 3 опор, реальные 3D границы joint/τ, положительное геометрическое и динамическое замыкание, физически достижимый 6→4 переход. Прежняя IDTO траектория годится как warm start; не считать её допустимым решением. Каждую новую полную траекторию затем независимо проверять исходным MuJoCo 500 Гц, включая 6→4 и ≥3 периода. Не объявлять глобальную невозможность по ограниченному поиску.

## Как повторить

Требуются отдельный подтверждённый TRI IDTO / Drake 1.30 build и *собственная* оригинальная Freenove CAD30-MuJoCo-модель из приватного Drive. `source_cad30_smoke.yaml` — исходный шаблон q-инициализации из предыдущего PR, не содержит meshes; путь к нему автоматически обнаруживается `generate_reference.py`. Сначала `generate_reference.py --trace-zip /private/math-trace.zip --out /tmp/periodic --steps 28 --dt .9 --iters 60`. Патч: `python patch_local_idto.py --source /private/pinned-idto/examples/example_base.cc`; повторный запуск патча отвергается. После сборки C++ присвоить переменные `CAD30_G1_NOMINAL_CSV=/tmp/periodic/nominal_4swing_drake.csv`, опционально `CAD30_G1_GUESS_CSV=/private/previous-q.csv`, `CAD30_G1_OUTPUT_PREFIX=/private/results/run`, `CAD30_DRAKE_MJCF=/private/converted-drake-box/mjcf/scene_local30_nominal.xml` и выполнить прежний CAD30 IDTO smoke executable **без `--test`**. Вывод полностью независимых экрано́в: `evaluate_trajectory.py --q ... --v ... --tau ... --model ... --reference-meta ... --math-zip ... --out ...`; затем `acceptance_screen.py` через `make_receipt.py`.

Для физической диагностики (не сертификата gait) — `physical_replay_from_virtual_start.py --model ... --q ... --reference-meta ... --math-zip ... --dt .9 --prefix /private/replay`; второй запуск дополнительно `--feedforward-tau /private/run_tau.csv`. Большие CSV, записи Fz/qpos/qvel/PD и исходные STL/OBJ — **только в личном Google Drive** с SHA256; в GitHub — исходники, методика, компактный JSON и тесты.
