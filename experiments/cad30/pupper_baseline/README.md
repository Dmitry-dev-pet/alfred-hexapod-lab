# Alfred Hexapod Lab — готовые Pupper Stance/Swing + Mink на оригинальной CAD30

**4 ноября 2026. Статус: подтверждённый динамикой переход 6→4 и ОДИН отрыв/перенос/постановка задней ноги; НЕ непрерывная четырёхногая походка.**

Связанные задачи: [Issue #38 — reuse готовой crawl-походки](https://github.com/Dmitry-dev-pet/alfred-hexapod-lab/issues/38), [Issue #21 — ходьба на четырёх](https://github.com/Dmitry-dev-pet/alfred-hexapod-lab/issues/21); исходный аудит готового `GaitController` в PR #37. Не развиваем самописный MPC из экспериментального PR #36, пока не заработает простой инженерный baseline.

## Что действительно исполнено

Физическая модель: FNK0052 CAD30 (30 оригинальных STL, **не включены в этот архив и GitHub**), собственная исходная сцена MuJoCo, движок 3.14.0. Nominal mass ~1.8048682 кг, nominal friction μ=1.1, PD Kp=7 / Kd=0.32, условные пределы моментов ±0.7 Н·м на ногах, шаг физики 0.002 с. Допустимые углы ±1.7 рад — **исследовательская гипотеза, не паспортные пределы сервоприводов**.

**Движение корпуса во всех прогонах получено только динамикой `mujoco.mj_step`; команды подаются суставам, не корневой позе.** После каждой фазы модель MuJoCo инициализируется из фактических `qpos/qvel` предыдущей физической фазы (корень не перемещается искусственно). Реакции контактов измеряются через `mj_contactForce`; количество нагруженных ног проверено на **каждом 2-мс такте** при рабочем пороге Fz>0.08 Н. Для подтверждения контакта после touchdown применяем более строгий порог Fz>0.2 Н.

### Последовательность из ИСХОДНОЙ шестиногой стойки

| Фаза | Готовый механизм | Фактический результат в модели |
| --- | --- | --- |
| Подъём корпуса | Физическая 6-опорная перестройка + известная локальная IK из проекта | +28.5884 мм по высоте; не менее 6 нагруженных ног на каждом такте; max |q| 1.4785 рад, пик 0.1592 Н·м |
| Подготовка нагрузки | **Stanford Pupper StanceController** (не наша новая траектория) + Mink IK | Команда на корпус −35 мм по +Y; фактическое −36.3937 мм, все 6 ног нагружены, пик 0.1671 Н·м, max |q| 1.4035 рад |
| Подъём передней пары | Mink кинематика передних `fl/fr`, задние не поджимаем (`rear_push=0`) | Реальные высоты `fl` 72.221 мм, `fr` 72.217 мм; min 4 нагруженные опоры `ml/mr/bl/br`, минимум запаса COM **21.6296 мм**, max |q|1.4138 рад, пик 0.3520 Н·м |
| **Один шаг `bl`** | Оригинальная формула **Stanford Pupper SwingLegController** + Mink + MuJoCo | Фактическое перемещение стопы вперед **20.3452 мм**, документированный отрыв и touchdown; от 3 нагруженных ног во время swing до 4 после touchdown; минимум физического геометрического запаса **21.1795 мм**, пик 0.42455 Н·м, max |q|1.6139 рад |

В последней фазе не было ни одного насыщения приводов; конечные нормальные реакции (Н): `ml` 8.149, `mr` 7.620, `bl` 0.535, `br` 1.402, передние обе 0. **Все четыре ходильные стопы реально вернули контакт** без дополнительной корректировки. Вся проверка выполнялась при модельном трении μ=1.1 на ровном полу.

**Важно о честном продвижении:** за 2-секундный swing + выдержку корпус по +Y почти не сдвинулся: **+0.0376 мм**, хотя задняя стопа переместилась +20.345 мм. Если считать от самой исходной шестиногой стойки (включая перенос веса), чистое перемещение корня корпуса по +Y равно **−34.3356 мм**, чистый перенос COM по Y **−29.0855 мм**. Это **НЕ положительная ходьба**; дополнительная подготовка не должна исключаться из метрики.

### Почему второй шаг пока не запускаем

В конце первого динамического шага рассчитана геометрия треугольника остальных трёх стоп при попытке отрыва каждой. При неизменном COM:

| Поднимаем | Signed margin текущего COM |
| --- | ---: |
| `bl` (левая задняя) | +21.543 мм |
| `br` (правая задняя) | +21.543 мм |
| `ml` (левая средняя) | **−82.089 мм** |
| `mr` (правая средняя) | **−91.463 мм** |

Это НЕ доказательство невозможности отрыва `ml/mr` после безопасного переноса веса, а **обязательный veto** следующего среднего шага из текущей позы. Готовый планировщик фаз Pupper, даже верно выдающий одну ногу в swing за раз, сам по себе не решает такую геометрию и не содержит необходимого для нашей конструкции автоматического веса/контактного контроля. До этого момента полный crawl не получен.

## Откуда взят код

- Готовые модули **Stanford Pupper v1**, оригинальный upstream commit [`dc0c5e2089cf2c0aac3c59982a4f140c31803175`](https://github.com/stanfordroboticsclub/StanfordQuadruped/tree/dc0c5e2089cf2c0aac3c59982a4f140c31803175): `src/StanceController.py`, `src/SwingLegController.py`, `src/Gaits.py`, MIT license. Исследовательский PR #37 уже содержит точную копию `Gaits.py` и лицензию; новый PR добавляет оригинальные Stance/Swing.
- В локальном экспериментальном ZIP находятся минимальные совместимые копии этих модулей (математика движения соответствует upstream); в GitHub закреплены исходники с оригинального коммита и уведомлением о MIT-лицензии. Локально также использован небольшой совместимый адаптер `transforms3d.euler.euler2mat` на `scipy.spatial.transform.Rotation`, который поддерживает лишь необходимые Euler XYZ.
- **Mink 1.4.0** решает IK для конкретных контактных `site` модели; совместимость и офлайн-пакет проверены ранее. Готовые библиотеки не вычисляют автоматически измеряемые нагрузки: guard по Fz, COM, torque и фактическим IK остается в минимальной адаптации CAD30.
- Подъём тела 6/6 — существовавшая в проекте кинематика, **не Pupper**. Переход 6→4 — совместная работа Pupper Stance + Mink и подъём передних ног Mink. Swing `bl` — Pupper Swing + Mink.

## Тесты и повторение

**8/8 локальных тестов PASS:** 3 unit-теста интерфейсов Pupper и 5 real-CAD30 MuJoCo integration tests, с точным учётом условий выше. Когда приватной CAD30 XML/мешей нет, интеграционные тесты **SKIP**, а не считаются успешными.

Потребуются восстановленная приватная CAD30 (включая `source/mjcf/scene_local30_nominal.xml` и оригинальные 30 STL), Python 3.13, NumPy, SciPy, MuJoCo 3.14.0, Mink 1.4.0 + DAQP, исходный пакет `hexlab` и сохранённый оригинальный upstream Pupper (в исследовательском ZIP имеется минимальный локальный вариант). Офлайн-зависимости: [Mink Linux cp313 wheelhouse на Google Drive](https://drive.google.com/file/d/1hnDaarQNdj5_Y94BJ9aNA4j2xRQ-kowv/view?usp=drivesdk).

~~~bash
export CAD30_ROOT=/path/to/restored/CAD30-root
python3.13 -m unittest discover -s . -p 'test_pupper_cad30_baseline.py' -v
# Единственный динамический swing `bl`, с полным 6->4 с начала:
python3.13 pupper_four_first_swing.py --mm 20 --mu 1.1 --out local_one_swing.json
~~~

Все четыре стадии сохранены отдельными полными JSON в приватном архиве. Более компактные receipts и SHA-256 исходников можно проверять непосредственно из GitHub.

## Следующий инженерный вопрос

Не добавлять самописный MPC. Сначала испытать **реальную 6-опорную подготовку другого footprint** или модуль обычного смещения веса Pupper с проверкой трёхопорного треугольника и досягаемости каждого сустава, затем повторить один `ml/mr` swing из устойчивого состояния. Если механика не допускает разумный перенос, исследовать перенос фактической массы, изменение длин/постановки опор или временную помощь передних конечностей. Только после этого можно говорить о нескольких циклах повторяемой ходьбы.

**Не считать ни один кадр или прогноз шагом, если не подтверждены фактический отрыв, постановка, реакции, пределы и чистое продвижение от исходного состояния. Не мержить draft PR без согласования.**
