# CAD30 → Drake / IDTO: решение ошибки Halfspace и первый численный smoke-run

Дата: 2026-11-05. Исследование [Issue #50](https://github.com/Dmitry-dev-pet/alfred-hexapod-lab/issues/50), математический протокол PR #53, baseline Drake/IDTO PR #33. **Это не доказанная ходьба.** Ни `main`, ни оригинальные Freenove CAD/STL/MuJoCo XML не изменяются; никаких команд железу.

## Проверенный результат

Встроенный IDTO от Toyota Research Institute, коммит `de0629c7811aa9b330e56c4385629005b09495f0`, с Drake 1.30.0 C++ **реально запускался** на исходной CAD30-модели (27 q / 26 v / 20 приводов) с сохранённой шестиопорной `q_init` после Pupper prebalance. При неизменённой контактной сетке каждой из шести голеней исходная Drake MJCF-плоскость превращается в `Halfspace`. В IDTO `ComputeSignedDistancePairwiseClosestPoints` падал с `Convex vs Halfspace not supported` (оригинальный лог сохранён отдельно).

**Исправление только для Drake:** заменить `worldbody/geom[@name="floor"]` с типом `plane` на большой конечный `box` с верхней гранью в прежнем `z=0`. В нашем тесте пол: half extents `2 × 2 × 0.05 м`, центр `z=-0.05 м`; исходные геометрия и суставы ног не меняются, оригинальные приватные `STL` переведены в `OBJ` без изменения вершин/граней. Это **не** утверждение контактно-динамической эквивалентности Drake/MuJoCo! Боковые грани и конечные размеры отличаются от бесконечной плоскости MuJoCo.

| Проверка | Фактически получено |

| Требуемый `world-Y` от сохранённого checkpoint | **+20.0 мм** |
| Терминальный `world-Y` корпуса из оптимизированной траектории | **+3.702 мм** (НЕ фактически пройденное расстояние в MuJoCo) |
| Максимальный выход оптимизированных актуаторов | **0.363948 Н·м**; модельный исследовательский cap ±0.7 Н·м **не был жёстко встроен в Drake** |
| `Max unactuated torque` | 0.0536305, это сообщение IDTO о неактуированных обобщённых усилиях, **не измеренная сила стопы** |
| Семь локальных тестов конвертера/receipt | **7/7 PASS** |

IDTO рассчитал **одну мягко ограниченную траекторию 0.5 с** (`10 × 0.05 с`), а **не** периодический цикл `ML/MR/BL/BR`; не проверены фактические силы под каждой стопой, минимум 3 контакта, проскальзывание, PD-воспроизводимость, полный цикл или положительный net от самого исходного шестиногого состояния. Начальная сохранённая стойка уже была смещена назад предыдущей подготовкой. Модельная `armature=0.002`, `frictionloss`, PD и моторные пределы не перенесены Drake Parser 1.30 один-к-одному — это отдельный gate перед G1/G2.

## Файлы

- `make_drake_box_floor.py` — изолированно **копирует** ранее конвертированный локальный CAD30 (с приватными OBJ, которые остаются у владельца), меняет **только** элемент пола, валидирует отсутствие иных модификаций; с входами не перезаписывает исходный каталог.
- `test_make_drake_box_floor.py` — инварианты положения верхней поверхности, сохранения приватных файлов, отказ при повороте пола/повторной записи.
- `cad30.cc`, `cad30.yaml`, `CMakeLists.txt` — минимальная цель в оригинальном дереве IDTO для нашего MJCF. Здесь `mpc: false`, никакой походки.
- `diag_format_compat.patch` — локальное исправление **только диагностического форматирования Eigen** для компоновки Drake/системного Eigen в исследовательском Debian13. Не изменяет оптимизатор.
- `g0_parity/` — ранее выполненная независимая cross-engine кинематическая проверка и локальный `STL→OBJ` конвертер; результаты численно сохранены без CAD.
- `make_result_receipt.py`, `test_make_result_receipt.py`, `results/IDTO_BOX_FLOOR_COMPACT_20261105.json` — машинные метрики и честные статусы.
- Полные stdout/stderr, входные хеши, вывод независимого Drake-probe — **только в личном архиве Google Drive** (без CAD/OBJ/STL).

## Воспроизведение в изолированной Linux x86_64 среде

1. Восстановить собственную CAD30 из личного Google Drive и exact upstream TRI IDTO commit, pinned Drake 1.30.0. Использовать только **локальные** CAD-меши — не добавлять их в публичный GitHub или отчёты.
2. `python g0_parity/convert_stl_to_obj.py --source /private/CAD30/source --destination /private/cad30-obj`
3. `python make_drake_box_floor.py --source-root /private/cad30-obj --output-root /private/cad30-drake-box --receipt /tmp/floor-receipt.json`
4. Скопировать `cad30.cc`, `cad30.yaml`, `CMakeLists.txt` в **новую локальную копию** upstream `idto/examples/cad30`; в upstream `idto/examples/CMakeLists.txt` добавить `add_subdirectory(cad30)`; при необходимости применить `diag_format_compat.patch` в той же локальной копии.
5. `cmake ... -Ddrake_DIR=/path/to/drake/lib/cmake/drake`, затем `cmake --build ... --target cad30_idto_smoke`. Точный линкерный sysroot Ubuntu Jammy должен быть доступен для Drake 1.30.0; сборка не проверяется на произвольном ноутбуке.
6. В рабочей директории **IDTO build** выполнить `CAD30_DRAKE_MJCF=/private/cad30-drake-box/mjcf/scene_local30_nominal.xml ./examples/cad30/cad30_idto_smoke` без `--test`, чтобы использовать `max_iters: 60` из YAML; `--test` принудительно ограничивает до 10 итераций.
7. Сопоставить `q[T]`, `q_nom[T]`, торки и статус; затем отдельно прогнать MuJoCo исходную сцену. Solver return=0 сам по себе — **не gait PASS**.

## Следующие ворота

1. **G0b — контакт/приводы:** проверить актуаторные ограничения, инерцию роторов, контактные силы и foot floor gaps на одинаковых состояниях в Drake и MuJoCo. При несовпадении корректировать только модель решателя, не подгоняя оригинальные данные.
2. **G1 — период:** задать жёсткие условия 4 swing/liftoff/touchdown, минимум три реальные опоры, замыкание суставов и стоп, положительное продвижение корпуса за цикл, включая подготовку. Если IDTO не выражает все жёсткие ограничения, взять существующий фазовый NLP/direct collocation в Drake вместо объявления PASS.
3. **G2:** независимая интеграция в **исходном MuJoCo** через ≥3 непрерывных цикла, без root teleport/reset, с логом всех Fz каждые 2 мс и net Y относительно исходной шестиногой стойки.

Все отчёты — с честным статусом `SOLVER_RUNS / WALK_NOT_YET_FOUND`; никакого merge в `main` без ревью владельца.
