# FNK0052 — минимальная локальная координация шести ног (эксперимент)

**Дата:** 2026-11-03. **Исполнение:** Python 3.13, MuJoCo 3.14.0 непосредственно в среде ChatGPT, без вычислений через GitHub Actions. **Статус:** разведочный физический эксперимент, не биологически подтверждённый алгоритм и не откалиброванный цифровой двойник.

## Исследовательский вопрос

Можно ли получить более регулярное согласование шести периодических движений без централизованного расписания ног? В отличие от неподвижного робота, **каждой ноге явно задан цикл опоры/переноса**. Мы проверяем только возникновение *межножного порядка* из локальных связей, а не спонтанное появление движения из неподвижного состояния.

## Три контроллера

Все шесть ног имеют независимые локальные таймеры опоры, контакты собственной голени, одну и ту же заранее рассчитанную IK-траекторию (35 мм горизонтально, 20 мм подъём), одинаковый PD-регулятор `τ = clip(7(q_target-q) − 0.32·q̇, ±0.7 Nm)`. Ноги делят один свободный механический корпус, но корпус **не двигается командами напрямую**. В начале каждой ноге случайно задаётся степень завершённости опоры; один и тот же набор используется во всех трёх вариантах (seed).

1. **independent**: нога сама начинает перенос, когда достигла конца своей опорной фазы и ещё находится в контакте. Никаких сообщений от соседей. Общее тело, следовательно, является единственным путём механического взаимодействия.
2. **neighbor_inhibit**: то же, но непосредственно соседняя нога в переносе запрещает начало своего переноса. Если две соседние ноги одновременно готовы, каждая разрешает конфликт по стабильному *локальному* приоритету соседней ноги; никакого глобального списка/сортировки кандидатов.
3. **neighbor_touchdown**: то же плюс краткий сигнал готовности соседям после *наблюдаемого* контакта собственной голени с полом.

**Ни в одной группе нет** глобального периода/фазового смещения tripod или wave, глобального лимита одновременных переносов, или общего барьера по опорному многоугольнику. Все решения рассчитываются на общем временном шаге физики и реализованы в одном Python-процессе. Это **логическая**, а не аппаратная распределённость. Текущие правила — **не** нейрофизиологическая модель Walknet/neuroWalknet.

## Модель и честные ограничения

Исходник — `MattiaGrigoli/autonomous_hexapod`, MJCF `5c9a84c16335b30036e451c691d2c544abf4bc72`. **30 из 32 оригинальных Freenove STL**, проверенных Git blob SHA; шесть настоящих `tibia.stl` выпуклых контактов, два недостающих STL (`topplate.stl`, `bigservo1.stl`) заменены визуальными блоками. Масса 1.804868 кг **расчётная**, как и трение, моторные моменты, распределение масс и параметры привода. Сервоприводы не калиброваны, реального робота не испытывали.

**Исходные CAD/3D не добавлены в GitHub** — отдельные авторские условия Freenove, см. upstream `LICENSE-3RD-PARTY.md`. Хранятся только в приватном Drive с манифестами. В экспериментальном ZIP нет оригинальных STL; его необходимо использовать вместе с предыдущим CAD30 ZIP проекта.

## Основной результат: пять стартовых состояний, 8 с, μ = 1.1

| Вариант | Среднее продвижение, см | Средний максимум наклона | Прогоны с <3 контактами | Насыщение момента, доля шагов |
|---|---:|---:|---:|---:|
| Independent | **9.093** | 2.846° | 5/5 | 0.645% |
| Neighbor inhibit | **11.832** | 0.594° | 1/5 | 0% |
| Neighbor + touchdown | **11.750** | 0.595° | 2/5 | 0% |

Все 15 испытаний закончились без критерия падения, все шесть ног совершали перенос. Локальное торможение улучшило среднее продвижение на **30.12%** относительно несвязанных ног на этих пяти стартах. Это не статистическое доказательство превосходства во всех условиях: размер выборки невелик, а базовое движение заранее задано каждому локальному контроллеру.

**20-секундный контроль, seed=23:** independent — **23.62 см**, inhibition — **30.308 см**, inhibition + touchdown — **30.137 см**. При inhibition минимум три контакта в 50-Гц записях; при независимых ногах минимум один контакт; добавление сигнала касания в длинном прогоне допустило кратковременные две опоры.

**Трение μ=0.6, только два старта (11 и 37):** ни один контроллер не гарантирует ≥3 контактов. Inhibit уменьшает долю опасных отсчётов по сравнению с independent, но минимум в одном прогоне остаётся только одна опора. Дополнительные сигналы касания иногда ухудшают поддержку. Нельзя называть нынешний контроллер безопасным на скользком покрытии.

## Почему это не «возникло из ничего»

- Периодический моторный цикл ног и локальное правило запрета соседних переносов **заданы явно**.
- Относительная временная последовательность **не задана**: она развивается из индивидуальной готовности, локальной конфликтной связи и механической обратной связи.
- Уменьшение наклона и опасных перекрытий при заданных пяти стартах — конкретный проверяемый эффект.
- Нельзя утверждать, что получена биологическая походка, обучение, нейронная сеть или подтверждённая физическая устойчивость робота.

## Воспроизведение

После восстановления исходного private Drive архива CAD30 (в каталог `experiments/cad30/`, включая `source/`, `hexlab/`, `data/`, `locomotion_cad30.py`, `local_contact_gait.py`) и кода из GitHub:

```sh
cd experiments/cad30
python -m unittest discover -s tests -p 'test_decentralized_ablation.py' -v
python decentralized_ablation.py --mode independent --seed 23 --seconds 8
python decentralized_ablation.py --mode neighbor_inhibit --seed 23 --seconds 8
python decentralized_ablation.py --mode neighbor_touchdown --seed 23 --seconds 8
python decentralized_ablation.py --mode neighbor_inhibit --seed 23 --seconds 20
python decentralized_ablation.py --mode neighbor_inhibit --seed 23 --seconds 8 --friction 0.6
python tools/create_decentral_receipt.py    # после всех 5 seed / всех серий
MPLBACKEND=Agg python tools/plot_liftoff.py
xvfb-run -a env MUJOCO_GL=glfw python tools/render_comparison.py
```

**Артефакты:** `results/decentralized_ablation_summary_2026-11-03.json` (итоговый фиксированный протокол), а также полные `results/decentral_*.json` с 50-Гц контактами, событиями подъёма/касания и состояниями 9-Гц для реального MuJoCo replay. Видео двух режимов на одном кадре отрендерено из настоящих `qpos` и не подменяет динамику.
