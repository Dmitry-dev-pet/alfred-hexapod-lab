# Hexapod Lab — MPC + WBC поверх MuJoCo

**Статус: 4 ноября 2026.** Архитектура утверждена для исследования, но полный MPC и динамический WBC **ещё не реализованы**. Два новых модуля — проверяемые математические заготовки, а не доказательство четырёхногой ходьбы. Issue #26 — прогноз полного цикла; #21 — ходьба на средних/задних при поднятых передних «клешнях»; PR #27 — предыдущий отрицательный тест позы B.

## Архитектура

\`\`\`text
MuJoCo: qpos / qvel / base / COM / foot contacts / Fz
  ↓
State estimator: общая мировая система координат, контакты и неопределённость
  ↓
Contact schedule planner: какая стопа уйдёт в swing, куда поставим её, 4 шага
  ↓
MPC: прогноз COM, корпуса, моментов и сил на последовательности будущих фаз
  ↓
WBC: согласованные малые изменения всех 18 суставов, не сдвигая опорные стопы
  ↓
Actuator dynamics + MuJoCo dt=2 мс; наблюдение → replanning
\`\`\`

Передние CAD-нôги \`fl/fr\` подняты, четыре несущие — \`ml/mr/bl/br\`. При выходе в swing только одной из четырёх остаётся минимум три опоры. Нельзя перемещать стопу по земле под нагрузкой, выдавая это за перестановку: на фазе stance положение точки контакта удерживается, для нового foot placement сначала разгружаем и поднимаем ногу.

## Что используем без переписывания

- \`optimized_claw_gait.py::physical_contact_forces\` — реальный мир MuJoCo: контакты, нормальные реакции, геометрия.
- \`support_wrench_qp.py\`, \`optimized_claw_gait.py::force_oracle\` — уже имеющийся LP/QP при известных q, COM, Jacobian и контактах; квазистатика, трение, моторный лимит. Нужно повторить проверку **для будущих**, а не только текущих контактов.
- PR #23/#25 — фактически полученная 6→4 стойка B; не полноценная походка.
- PR #27 — поиск в ограниченной геометрической постановке дал отрицательный результат; он **не** говорит о невозможности произвольных четырёхногих траекторий.

## Математические модули в этой ветке

**\`horizon_contact_gate.py\`** — принимает снаружи кандидаты полного цикла из четырёх подъёмов/постановок, а не генерирует их. На отдельных этапах проверяет:
1. Треугольник трёх оставшихся опор и запас COM ≥5 мм во время swing.
2. Четырёхопорный полигон и COM после touchdown.
3. Дальность предложенной перестановки ≤50 мм; продвижение COM за полный цикл ≥20 мм.
4. Консервативный терминальный критерий: из заключительной точки COM должна быть доступна хотя бы одна следующая трёхопорная стойка без предварительного переноса корпуса.

Проверка возвращает «допустимая **необходимая геометрия**» или объяснение отказа, выбирает лучший из поступивших кандидатов. Она **не проверяет** непрерывность между узлами, коллизии, IK, трение, моменты, динамику, нагрузку; прохождение фильтра не разрешает выдавать моторную команду.

**\`wbc_contact_correction.py\`** — на основании *предоставленных реальных якобианов* решает линейную локальную задачу

\[
J_{\text{base}}\Delta b + J_{\text{joints}}\Delta q=0,
\]

минимизируя отклонение опорных точек при малом заданном движении корпуса. Четыре контактные ноги могут одновременно менять суставные углы; свободные передние ноги могут выполнять отдельные малые позные команды. Решатель автоматически отклоняет чрезмерное движение корпуса, недостижимый контакт, выход за суставные ограничения, превышение локального шага или линейного невязочного допуска.

Параметры тестовой математики по умолчанию: ≤2 мм поступательное изменение корпуса, ≤0.005 рад его вращение, ≤0.02 рад приращение сустава, ≤20 мкм **линейной прогнозной** ошибки стопы. Они **не являются паспортными ограничениями приводов, не гарантируют реальное отсутствие скольжения и не подразумевают измеренную точность**.

## Проверка

С NumPy и SciPy из \`experiments/cad30/\`:

\`\`\`bash
python -m unittest -v test_wbc_contact_correction.py test_horizon_contact_gate.py
\`\`\`

13/13 локальных тестов прошли на **синтетических данных** (искусственные контактные якобианы и опорные четырехугольники). Проверены совместные корректировки, ограничения, отказ при недостижимой позе и случай, когда второй шаг нарушает прогноз и потому запрещён первый. Это не тест реальной CAD30 кинематики.

## Что делать дальше (строгие ворота)

1. Подключить к локальному CAD30 MuJoCo *текущие* qpos и реальные якобианы опорных контактов. Сверить предсказанное \`J_b db + J_j dq\` с \`mj_forward\` конечной точки при малых приращениях; проверить, что целые 18 каналов и их знаки сопоставлены верно. До этого не подавать команды на физический робот.
2. Реализовать генератор кандидатных будущих contact schedules: перебор порядка, точек touchdown в 2D и будущей 6D позы корпуса (включая высоту, pitch/roll). Никаких искусственно фиксированных «все стопы на +Y».
3. Проверять *все* узлы и непрерывные переходы через joint IK, collision, \`support_wrench_qp\`, конусы трения, пределы моментов, запас COM и будущую жизнеспособность; не считать одношаговый успех походкой.
4. Выполнить receding-horizon replanning из **измеренного** состояния после каждого touchdown/неожиданной смены контакта; при infeasible — hold, controlled recenter или безопасный возврат к 6 опорам, без насильственного отрыва.
5. Затем провести независимый свободнобазовый MuJoCo rollout (dt=2 мс, реальные контакты, >=3 несущих ноги на каждом такте, один lift/touchdown каждой из четырёх, ≥20 мм чистого продвижения). Зафиксировать силы, slip, torque, margin, COM, collisions и полную трассу. Только затем 3D viewer или перенос на железо.
