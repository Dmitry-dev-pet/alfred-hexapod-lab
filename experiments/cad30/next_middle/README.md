# CAD30 — попытка продолжить crawl после успешного `ml` (5 ноября 2026)

**Статус: второй перенос стопы `mr` физически получен, но строгий квазистатический критерий НЕ пройден. Это не полная четырёхногая походка.** Исходный робот не приводился в движение. `main` не меняем, PR draft, не merge без владельца.

## Зачем

После [PR #45](https://github.com/Dmitry-dev-pet/alfred-hexapod-lab/pull/45) физически подтверждён `ml` swing из реально измеренного состояния. Следующая логичная нога `mr` имеет положительный *геометрический* запас COM в треугольнике `ml/bl/br`: **+26.69 мм**. Но наличие геометрического запаса ещё не гарантирует сохранения трёх измеренных контактов: штатный позиционный PD (`Kp=7`, `Kd=0.32`) периодически теряет Fz на `ml` и иногда `bl/br` в начале `mr` swing.

## Что действительно запущено

- Оригинальная CAD30-модель FNK0052 с 30 приватными STL, MuJoCo 3.14, шаг физики **2 мс**, масса ≈1.805 кг, номинальная μ=1.1, условные ограничения |τ|≤0.7 Н·м, |q|≤1.7 рад. Моделирование только локальное, ни бинарные CAD, ни mesh не публикуются.
- Более 60 независимых небольших параметрических испытаний после **физического `ml`**: изменения относительного смещения корпуса, продолжительности команд, PD damping, небольшие коррекции toe Z, а также непосредственно угловых команд stance `ml` (femur, tibia).
- Самый существенный локальный эффект был достигнут прямой коррекцией команд `ml` femur −0.075 rad, tibia +0.055 rad. Она уменьшает число тактов с недостаточной реакцией хотя бы одной необходимой опоры, но не до нуля. Это *команды приводам*, не искусственный сдвиг позы корпуса.
- **Непрерывная физическая последовательность, в одном `MjData`:** от сохранённой шестиногой стойки PR #40 через 17 675 шагов старой подготовки, физический `ml` из PR #45, затем `mr` с pre-shift (+20 мм по Y) и микрокоррекцией `ml`. Между фазами нет `mj_resetData` и нет записи в корневые `qpos`.

**Важно:** положительная мировая перестановка стоп не равна положительному движению корпуса от начала опыта. Отрицательный общий прогресс не скрывать. Результат `mr` **FAIL** по ранее установленному критерию нагрузки ≥3 опор на **каждом** физическом 2-мс такте. Полный четырёхшаговый цикл не проверен, испытания `bl/br` в этой непрерывной цепочке не выполнены.

Провалы Fz краткие (один такт) и могут быть связаны с физической микродинамикой/контактным дребезгом, но это **не доказано**. Нельзя заменить строгий критерий средним Fz без отдельной новой спецификации. Требуется явно сохранять и проверять мгновенные контакты, углы и моменты.

## Два пути проверки перед продолжением к задним ногам

1. **Управление по модели:** оптимизировать целевые углы stance через короткие free-base MuJoCo rollouts по минимальному Fz и времени потерь, добавить причинно-замкнутую коррекцию по `Fz` (в симуляции), не просто входной bias.
2. **Физическая/численная идентификация:** проверить, исчезает ли 2-мс contact chatter при изменениях `dt`, моделей податливости стоп, демпфирования, без фальсификации результатов исходной модели; затем оценить, нужен ли реально иной тип контакта или датчики.

Задние `bl/br` геометрически требуют нового переноса COM, и продолжать их через непроверенный второй шаг как успешный crawl нельзя.

## Повторение

Код наследует `ModelStudy` и `read_contact` из стека PR #43–#45. Требуются приватная модель CAD30, Python 3.13, MuJoCo 3.14.0, SciPy, NumPy и собственный `hexlab`. Файлы и входные данные обозначены в PR #45 и сохранены в Drive; прямых аппаратных команд нет.

```bash
export CAD30_ROOT=/path/to/restored/cad30
python -m unittest discover -s experiments/cad30/next_middle -p 'test_*.py' -v
python experiments/cad30/next_middle/mr_contact_continuation.py \
  --cad-root "$CAD30_ROOT" --repo-root . \
  --checkpoint experiments/cad30/next_middle/results/after_ml_physical_checkpoint_20261105.json \
  --leg mr --step-mm 33 --clearance-mm 18 --node-s .35 --shift-y-mm 20 \
  --servo-femur -0.075 --servo-tibia 0.055 \
  --out /tmp/actual_mr_replay.json --raw
```

Полное непрерывное воспроизведение от шестиногой стойки: `replay_six_ml_mr.py` с явными параметрами `--cad-root`, `--repo-root`, `--six-state`, `--math-trace`, `--physical-trace`, `--optimized-ml`, `--out`, `--raw`. См. исходный код. Для каждого результата статус отдельно: `ml=PASS`, `mr=FAIL`, `gait=NOT_ACHIEVED`.
