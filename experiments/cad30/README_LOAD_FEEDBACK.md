# FNK0052 / CAD30 — замкнутое управление по нормальной силе опор, 3 ноября 2026

## Научный вопрос

Улучшает ли добавление **нормальной силы опоры** (вместо одного лишь бинарного контакта) координацию шести локальных контроллеров ног без центрального расписания?

**Статус:** локальный численный эксперимент MuJoCo 3.14.0 в вычислительной среде ChatGPT; **не** реальный робот, не цифровой двойник с измеренными параметрами, не нейронная система Walknet. GitHub Actions **не** использовался для вычислений.

Используется CAD30, восстановленный из закреплённого upstream MJCF MattiaGrigoli@`5c9a84c16335b30036e451c691d2c544abf4bc72`: 30 оригинальных STL с проверенным SHA Git blob, настоящие исходные сетки шести голеней для контакта (MuJoCo рассматривает меш-контакт через выпуклую оболочку), 18 приводов ног + 2 приводов головы, расчётная масса 1.804868 кг; отсутствующие `topplate.stl` и `bigservo1.stl` заменены **только в визуализации**. Моделируются жёсткие тела, гравитация, трение и динамика опор, корпус свободен. PD с `Kp=7`, `Kd=0.32` и условной границей ±0.7 Н·м. Источники CAD и лицензия Freenove: https://github.com/MattiaGrigoli/autonomous_hexapod/blob/main/LICENSE-3RD-PARTY.md.

## Какая «нагрузка» измеряется

На каждом шаге физического движка (2 мс) вызывается `mujoco.mj_contactForce(...)`. Для каждой ноги суммируется первая (нормальная) компонента силы во **всех контактах её `tibia..._collision_0` с полом**. Непосредственно после устойчивой стойки 1.804868 кг суммарная нормальная сила всех опор равна примерно **17.706 Н** (вес модели); каждая нога несёт приблизительно **2.77–3.14 Н**. Данные не являются замерами датчиков на железе. Для принятия решений сила сглаживается EMA с постоянной 50 мс; реальная датчиковая задержка, шум, износ стоп и электрические ограничения отсутствуют.

Один локальный контроллер имеет собственный цикл **опора → перенос → подтверждение касания** и видит только собственные сенсорные данные, а в зависимости от варианта — состояние и нагрузку двух соседних ног. Глобальные фазовые сдвиги tripod/wave, сортировка готовности и центральная команда смещения корпуса отсутствуют. Сравнение включает:

* `neighbor_inhibit` — прежний базовый контроллер: соседняя нога в переносе тормозит подъём; собственный контакт должен подтверждаться.
* `neighbor_force_gate` — базовый + запрещает подъём, если **сглаженная собственная нормальная сила** выше 1.4 × (масса·g/6), то есть **4.13 Н** для 1.805 кг.
* `neighbor_force_gate_supported` — предыдущий + требует, чтобы **каждая из двух соседних ног** несла не менее 0.35 × (масса·g/6), то есть примерно **1.03 Н**. Другие четыре ноги в этом локальном решении не учитываются.

Это заранее выбранные пороги для **первой проверяемой гипотезы**, а не оптимизированный или биологически обоснованный закон управления.

## Одинаковый план абляции и результаты

В каждой группе те же начальные локальные фазы/приоритеты всех ног; 8 секунд после 1 секунды стабилизации, шаг 35 мм, подъём 20 мм, локальный период 2.4 с, одинаковые CAD, трение, моменты и параметры сервоприводов. Пять стартов для μ=1.1 (11,23,37,51,97); три для μ=0.6 (11,23,37); два для μ=0.3 (11,23). 10 условий × 3 способа управления = **30 физических прогонов**. Все завершились за 8 секунд без достижения критерия падения (высота корпуса <7.5 см либо наклон >50°); это не равносильно непрерывной статической устойчивости.

**Отрицательный результат.** На μ=1.1 прирост скорости статистически неубедителен и фактически равен нулю. При μ=0.6 уменьшение потери опор есть лишь в некоторых запусках; при μ=0.3 у всех трёх методов встречается **0 одновременно контактирующих ног** по 50-Гц протоколу. Нельзя говорить, что нагрузочная обратная связь сделала походку устойчивой.

Проверка реализации: в MuJoCo при ровной стойке сумма нормальных сил ≈ весу модели; 8 локальных тестов на измерение силы и разрешение/запрет подъёма проходят. На динамическом шаге **сырые силы скачут** (пример — до ~13 Н на одной ноге): из-за фильтра 50 мс даже при граничной сглаженной нагрузке ~4.13 Н фактическая мгновенная сила иногда значительно выше. Поэтому порог **не является гарантией безопасной разгрузки ноги**.

## Интерпретация

Алгоритм действительно использует новый сигнал, но **только откладывает** подъём тяжело нагруженной ноги, не регулируя распределение сил между оставшимися ногами. Это объясняет слабый эффект на ровном полу: чтобы существенным образом перераспределять нагрузку, нужны активная коррекция стойки/высоты корпуса, управление усилием в опорной фазе, оценка скольжения и более реалистичная модель податливой стопы. Следующие опыты должны контролировать безопасность не только по 20-мс кадрам, но по каждому 2-мс шагу; добавить задержку/шум датчика и независимые начальные состояния за пределами пяти использованных здесь.

Слабость текущей проверки: нет измеренных характеристик электрических сервоприводов, датчиков силы, напряжения/нагрева и сцепления резиновой стопы; нет неровного рельефа и приложения внешних возмущений. Отсутствие падения в таком эксперименте не гарантирует перенос на реального Freenove.

## Как повторить

Восстановить два ранее сохранённых набора проекта из Drive: `FNK0052_CAD30_local_MuJoCo_experiments_2026-11-03.zip` (для `source/`, `hexlab/`, `data/`, `models/`) и `FNK0052_decentralized_gait_ablation_2026-11-03.zip` (для `decentralized_ablation.py`). Добавить из этого архива `load_feedback_ablation.py` и `create_load_feedback_receipt.py` в ту же папку, что и `decentralized_ablation.py`, `locomotion_cad30.py`, `local_contact_gait.py`. Потребуются Python3.13, MuJoCo3.14, NumPy, SciPy, FFmpeg/GLFW для рендера, но не для самой физики.

```bash
python -m unittest discover -s tests -p test_load_feedback_ablation.py -v
python load_feedback_ablation.py --mode neighbor_inhibit --seed 23 --friction 0.6
python load_feedback_ablation.py --mode neighbor_force_gate --seed 23 --friction 0.6
python load_feedback_ablation.py --mode neighbor_force_gate_supported --seed 23 --friction 0.6
python create_load_feedback_receipt.py
python plot_load_feedback.py
xvfb-run -a env MUJOCO_GL=glfw python render_load_feedback.py
```

Архив включает полные 30 JSON-трасс (50 Гц нагрузки/контакты и 9 Гц положения всех суставов), PNG диаграмму реальных сил, MP4/GIF из сохранённых состояний MuJoCo и SHA-256 манифест. Оригинальные STL **в новом архиве не дублируются** и остаются в приватном Drive согласно условиям Freenove. Исходные коды и маленькая сводка фиксируются в черновом PR, не сливать без одобрения пользователя.
