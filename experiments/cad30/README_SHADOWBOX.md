# Эксперимент: высокая стойка и два «удара» передними ногами в воздухе

Дата: **4 ноября 2026 года**. Система: Freenove FNK0052, CAD30 / MuJoCo 3.14.0, Python 3.13.

**Это воспроизводимое численное моделирование; не испытание реального робота.** Нет контакта с целью, ударной нагрузки или измеренной силы удара. Не заявлено нейронное/автономное обучение: движение составлено из заранее заданных траекторий суставов. Следующая исследовательская задача — получать такую позу из обратной связи отдельных ног.

## Кинематика и экспериментальный протокол

- Исходная модель: MattiaGrigoli/autonomous_hexapod @ `5c9a84c16335b30036e451c691d2c544abf4bc72`; 30 проверенных оригинальных STL, недостающие две детали заменены **только в визуализации**. Контакты шести исходных геометрий tibia c плоскостью пола. CAD-активы не публикуются в GitHub из-за отдельной лицензии Freenove.
- Массы модели (предположения): **1.644 / 1.804868 / 2.080 кг**. Коэффициенты трения: μ=**1.1 / 0.6 / 0.3** (все условные).
- Модель двигателя: позиционный PD `Kp=7`, `Kd=0.32`, предел момента **±0.7 Н·м**. **Никаких проверенных параметров реальных MG996R, кривой момент–скорость, PWM, люфта, нагрева, электрических ограничений и питания нет.**
- Протокол 10 с после 1 с начальной устойчивой стойки:
  1. 0–2 с: смещение целевых точек четырёх средних/задних опорных ног на 40 мм вперёд относительно тела, что заставляет корпус **физически** сместиться назад. Корень и стопы не фиксируются и не перемещаются напрямую.
  2. 2–3.1 с: обе передние лапы поднимаются, целевые координаты каждой точки стопы относительно начальной: **+140 мм по Z и +50 мм по Y**. Следующая фаза — короткое удержание.
  3. 3.55–4.20 с: первая передняя нога выдвигается до цели +90 мм по Y (командное дополнительное выдвижение 40 мм) за 0.32 с, затем убирается; 4.45–5.10 с — то же другой передней ногой. **Выпады не касаются препятствия.**
  4. 5.55–10 с: опускание двух передних ног, восстановление исходного положения четырёх остальных, пауза для стабилизации на шести ногах.
- Решение IK ограничено **±1.7 рад** в каждой координате, но это **не** паспортный диапазон серв. Срабатывает ограничитель момента MuJoCo. Действительные точки контакта и COM оцениваются динамическим решателем, а не рисуются.
- **Строгий критерий** в интервале 3.25–5.45 с: не менее 45 мм просвета нижнего CAD-меша передних ног, отсутствие их контактов, четыре контакта опорных ног, запас COM внутри контактного многоугольника более 2 мм, наклон корпуса менее 10°, обе лапы реально продвинулись вперёд минимум на 12 мм, нет насыщения ограничителей момента. Отдельно фиксируется более слабый критерий контактов/баланса без требования об отсутствии насыщения.

## Главное наблюдение, номинал 1.805 кг, μ=1.1

| Метрика физической симуляции | Результат |
| --- | ---: |
| Минимальный фактический просвет исходного CAD-меша передних стоп | **103.84 мм** |
| Дополнительное фактическое выдвижение передней левой/правой ноги | **36.78 / 36.69 мм** |
| Минимальный запас проекции COM по фактическим контактным точкам | **22.30 мм** |
| Максимальный наклон корпуса во время высоко поднятых ног и выпадов | **2.681°** |
| Максимальный модуль момента в десятисекундном цикле | **0.48026 Н·м** |
| Насыщение условного ограничителя момента | **0% отсчётов** |
| Повторная стойка на шести ногах в последнем полусекундном окне | **100% отсчётов** |

**Важно:** +140 мм — командное смещение выбранной точки стопы в начальной позе; **103.84 мм** — минимальный зафиксированный просвет нижнего CAD-меша в динамическом окне трюка. Эти величины не тождественны.

## Контрольная матрица (без подстройки траектории)

| Сценарная масса | μ=1.1 | μ=0.6 | μ=0.3 |
| --- | --- | --- | --- |
| 1.644 кг | Успех | Успех | Неудача: потеря контактов, насыщение |
| 1.805 кг | Успех | Успех | Неудача: потеря контактов, насыщение |
| 2.080 кг | Успех | **Контакты есть, но 14.06% времени — насыщение** | Неудача: потеря контактов, насыщение |

Итого **6/9** опытов удовлетворяют условию контактов и баланса; **5/9** дополнительно проходят строгое условие ненасыщения приводов. Это **не доказательство безопасной работы на реальном аппарате**: скоростные/энергетические ограничения, контактное трение и масса реального робота не откалиброваны.

### Отрицательный контроль: зачем сдвигать корпус назад

При массе 1.805 кг и μ=1.1 без подготовительного сдвига (`shift=0`) трюк не проходит. При `shift=20 мм` лапы отрываются от земли, но четыре опоры не удерживают непрерывный контакт. При 30 и 40 мм условие выполняется, но запас COM при 40 мм больше (~22.3 вместо ~15.1 мм). Эти числа зависят от нашей контактно-моторной модели.

## Как воспроизвести

1. Восстановить только локально исходные CAD-активы `source/meshes` и MJCF `source/mjcf` из **приватного** Drive-архива `Alfred-Hexapod-Lab/Freenove-CAD-source`. Сначала сверить SHA по pinned manifest и запустить `build_30meshes.py`. Не добавлять оригинальные STL в GitHub.
2. Из корня репозитория:

```bash
python experiments/cad30/shadowbox_front_pair.py --lift 0.14 --guard-forward 0.05 --jab-forward 0.09 --shift 0.04 --mass nominal --mu 1.1 --record --out results/shadowbox_nominal_true_physics.json
python experiments/cad30/sweep_shadowbox_front_pair.py
python -m unittest discover -s experiments/cad30 -p 'test_*.py' -v
MUJOCO_GL=egl python experiments/cad30/render_shadowbox_front_pair.py results/shadowbox_nominal_true_physics.json results/shadowbox_media
```

3. Обязательные выходы: числовая сводка `results/shadowbox_front_pair_summary_2026-11-04.json` в GitHub; полные `trace`/`qpos_frames`, MP4, GIF, ключевой кадр и SHA-манифест — в приватной папке `Alfred-Hexapod-Lab` на Drive.

При вызове из текущей локальной CAD30-папки `source/` и `hexlab/` разрешены тем же кодом через обнаружение корня. **Все числа — из MuJoCo с реальной массой и контактом в симуляции; не из постановочного рендера.** Видео показывает кадры из сохранённого `qpos`, с дискретизацией для экономного рендеринга.

## Следующий научный этап

Отключить заранее заданный перенос на 40 мм: каждая средняя/задняя нога получает локальные оценки контакта и нагрузки, меняет опорную позу, обменивается только соседними сигналами. Передние ноги допускают подъём и выпад только когда стабилизирована нагрузка на четыре опоры. Сравнить с текущей запрограммированной базой на одинаковых случайных начальных условиях, трении, толчках, шуме IMU и задержках датчиков. Это будет проверкой распределённой координации, **а не просто эффектной хореографии**.
