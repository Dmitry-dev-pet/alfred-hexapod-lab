# FNK0052 CAD30 — математическая оптимизация сил опор (4 ноября 2026)

**Результат:** реализован и локально исполнен **математический эталон** для проверки возможности квазистатического равновесия при отключении одной или двух опор. Это не новый контроллер ходьбы, не нейросеть, не физическая калибровка Freenove и **не доказательство устойчивой ходьбы**. В расчетах используется **централизованная** информация о всех ногах: сравнивать с локальными алгоритмами можно только как с верхним ориентиром.

## Проверенная физическая модель и воспроизводимость

- Исполнялась существующая CAD30/MuJoCo 3.14.0: верифицированные 30 из 32 оригинальных STL по ссылке проекта; две недостающие STL — исключительно визуальные прокси; **эти исходные STL в GitHub/данный архив не копируются**.
- Nominal mass: **1.8048682 кг**, вес **17.70575704 Н**. Начальная поза — реально устоявшаяся шесть-опорная стойка после 1 секунды динамики MuJoCo, без фиксации корпуса и стоп. Полный исходный CAD30 ZIP хранится в отдельном приватном Drive.
- Модельной позе соответствуют центр масс (0.000119, 0.008035, **0.112675**) м, шесть геометрических опорных точек (у каждой голени две физические контактные точки). Для статической задачи они агрегированы в одну силовзвешенную точку **на каждую ногу**. Суммарная опорная реакция на исходной стойке воспроизводит вес.
- 20 моторных каналов, предполагаемые границы **±0.7 Н·м** для 18 суставов ног и ±0.2 Н·м для двух каналов головы; это численные гипотезы, НЕ измеренные реальные ограничения непрерывных усилий, скорости и температуры. При расчёте потери опоры массу конечности сохраняем — **не физическая ампутация**.
- Реконструкция требуемых суставных моментов: `mj_rne` (гравитационные обобщённые силы) минус `Jᵀ F` от физического контакта в MuJoCo. Сверка с управляющими моментами в стабилизированной исходной стойке даёт **максимальное расхождение 0.003892 Н·м**. Нельзя использовать `mj_inverse` с уже включёнными решателем контактными силами: это привело бы к двойному учёту контактов.

## Уравнения

Для каждого активного контакта `i` решаем неизвестную трёхмерную реакцию `f_i=(F_x,F_y,F_z)`. Для отключённой ноги принудительно ставим `f_i=0`.

```text
Σ_i f_i + m*g_vector = 0                       (баланс сил)
Σ_i (p_i - COM) × f_i = 0                      (баланс моментов)
F_zi >= 0                                    (односторонняя нормальная реакция)
||f_i,xy||_2 <= mu * F_zi                    (конус трения Кулона)
tau = h_gravity(q) - Σ_i J_i(q,p_i)^T f_i    (обобщённая статика)
|tau_j| <= tau_limit_j                       (все 20 модельных моторов)
```

Трение для строгой линейной проверки аппроксимировано **вписанным 32-гранным многоугольником**, который лежит ВНУТРИ истинного конуса, поэтому найденные там решения выполняют и исходное физическое ограничение трения. Если решение **не найдено**, дополнительно решается задача с **описанным** 32-гранным многоугольником. Если даже она невозможна — истинный конус тоже не даст статического равновесия в заданной позе. Для одного пограничного варианта при μ=0.3 дополнительно найдено решение с точным круглым конусом (SLSQP, проверенные численные невязки менее 1e-7); это численное свидетельство на границе, а не строгая гарантия с запасом.

Технология: `scipy.optimize.linprog(method="highs")` для **feasibility**, `minimize(method="SLSQP")` для вторичной цели минимизации отклонения сил от исходной стойки. Дополнительная **линейная задача минимизации максимальной доли использования моторов** позволяет не путать произвольный оптимум сил с неизбежным насыщением привода:

```text
min t,  subject to |tau_j| <= t * tau_limit_j
           + all wrench/friction/normal-force constraints
```

Эти два целевых критерия различаются: минимальное изменение сил может требовать 100% доступного момента, хотя ДРУГОЕ распределение при той же геометрии может использовать гораздо меньше.

## Численный результат в ОДНОЙ фиксированной стойке

Всего **66 вариантов**: шесть-опорная стойка, 6 вариантов убрать одну опору, 15 вариантов убрать две, всё по три коэффициента трения μ=1.1 / 0.6 / 0.3. Устойчивость во времени не моделировалась в этих дополнительных случаях: это математический анализ зафиксированной геометрии после исходного MuJoCo settle.

| Трение | 6 ног | потеря одной ноги (6) | потеря двух (15) |
|---|---:|---:|---:|
| μ=1.1 | возможно | **6/6** | **12/15** |
| μ=0.6 | возможно | **6/6** | **12/15** |
| μ=0.3 | возможно | **6/6** | **11/15** при строгой линейной аппроксимации + **1/15** с численным точным конусом. Итого 12/15 при нулевом резерве одного варианта. |

Три сочетания без возможной статической опоры во всех μ: CAD `ml+fl`, `mr+fr`, `fr+fl`. Во всех случаях проекция центра масс выходит за границу оставшегося опорного многоугольника (пример: удаление двух передних `fr+fl` оставляет **минус 8.015 мм** запаса). Обозначения CAD зеркально отличаются от сервисной нумерации Freenove: в частности CAD `fl` — vendor FR. **Не перепутать моторы.**

Примеры при μ=1.1:
- Отнять **одну** CAD `fl`: запас полигона +101.222 мм, расчётный оптимум сил предъявляет ~**5.185 Н** средней `ml` и ~**5.174 Н** передней `fr`; модель способна удерживать в условной статике. Минимальная возможная доля номинального мотора по отдельной оптимизации **27.88%** (при иных силах, чем в приведённом примере).
- Удалить **обе средние** `ml+mr`: запас геометрии **+142.067 мм**, моторный минимум **27.15%** условного лимита, статическое решение есть.
- Удалить `ml+bl`: запас геометрии **только +4.786 мм**; минимальное необходимое использование моторов **56.54%**. При оптимизации «ближайших к старым» сил момент действительно доходит до лимита, но это **не неизбежно**: альтернативное распределение, оптимизированное по моментам, имеет заметный резерв. Ограничение здесь прежде всего геометрическое, а не чисто моторное.
- Удалить `br+mr` при μ=0.3: статическое решение найдено с точным круговым ограничением трения, но один мотор использует **100%** допущенного максимума (практически нулевой запас); его нельзя считать робастно допустимым.

### Почему первоначальный результат μ=0.3 уточнён

У грубого вписанного **ромба трения** получалось лишь 10/15 двухопорных случаев. Более точный вписанный 32-гранник даёт 11/15, а оптимизация с **точным круговым** конусом даёт ещё один пограничный случай, 12/15. Это эффект точности численного ограничения, а НЕ изменение геометрии или моторной модели. Результаты всех приближений и неудачных комбинаций сохраняются; подгонки по выбору начальных состояний нет.

## Научные ограничения и дальнейший эксперимент

1. **Feasible ≠ безопасный шаг.** Замороженная поза с квазистатическими силами не говорит, успеют ли сервоприводы разгрузить ногу, удержатся ли контакты на скользком полу и есть ли запас к внешним воздействиям.
2. Контактная сетка голени в MuJoCo — выпуклая оболочка; два реальных контакта одного звена агрегированы в одну точку. Модель не учитывает распределённый контактный момент стопы, податливость, люфты, датчиковые задержки/шум, скорость/нагрев/ток реальных приводов. Массовые параметры не измерены.
3. Глобальный расчёт из всех ног **не является** «локально возникающим поведением». Следующая проверка — брать прогноз возможных сил как **эталон** и учить существующий локальный контроллер подходить к нему через сообщения соседних ног. Только после этого проверить динамику с более быстрыми шагами, воздействиями и изменениями центра масс.
4. Следующий динамический уровень должен учитывать `ΣF + m g = m a_COM` и `Σ(p-COM)×F = dL/dt`, а при упоре двигателей — ограничения предельно допустимого `τ`, скорости и контактов; статический oracle не должен незаметно подменять динамическую проверку.

## Как воспроизвести локально (НЕ через GitHub Actions)

Восстановить первичный приватный CAD30 ZIP проекта в каталог, содержащий `source/` и `hexlab/`, а исходники этого этапа добавить в `experiments/cad30/`:

```sh
cd /path/to/restored-cad30
python -m pip install 'mujoco==3.14.0' numpy scipy matplotlib
python experiments/cad30/support_wrench_qp.py \
  --out results/cad30_static_support_force_report_2026-11-04.json
CAD30_ROOT="$PWD" python -m unittest discover -s experiments/cad30/tests \
  -p test_support_wrench_qp.py -v
python experiments/cad30/plot_static_support.py \
  --input results/cad30_static_support_force_report_2026-11-04.json \
  --out results/cad30_static_support_polygons_2026-11-04.png
```

**11/11 новых локальных unit/integration tests пройдены** на исходных CAD30 данных. Полный 66-сценарный JSON, график, исходники/тесты и SHA-256 хранятся в архиве Drive. Компактный числовой протокол и код — в отдельной экспериментальной ветке GitHub. Предыдущие PR #4, #13, #15 не сливать автоматически; `main` не трогать.
