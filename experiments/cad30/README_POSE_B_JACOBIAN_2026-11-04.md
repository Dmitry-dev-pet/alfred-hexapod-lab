# CAD30 — проверка якобианов и WBC-коррекции на физически сохранённой позе B

**4 ноября 2026. Статус: KINEMATIC_ONLY_PASS.** Это проверка кинематики, не испытание ходьбы или динамических приводов.

## Проведённый расчёт

Из исходного архива FNK0052 CAD30 восстановлена сцена MuJoCo 3.14.0 с 30 STL-мешами, 27 qpos, 26 обобщёнными скоростями и 20 каналами приводов (18 ног + 2 головы). Начальная поза — ранее физически просчитанная B (semi_tucked) из записи при t = 9.3 с: четыре настоящие опоры ml/mr/bl/br, по две контактные точки на каждой, передние fl/fr подняты.

Из mj_jac построены якобианы четырёх опорных контактных маркеров. Их 24 столбца (шесть степеней свободы корпуса плюс 18 суставов ног) независимо проверены центральными конечными разностями по mj_integratePos и mj_forward при epsilon = 1e-6. Максимальная невязка равна 9.3352125e-11 (единицы производной м/м либо м/рад), RMSE = 1.1252749e-11.

В качестве пробной задачи задано перемещение корпуса [0,+0.35,-0.10] мм и вращение [0.0003,-0.0002,+0.00015] рад. Существующий модуль wbc_contact_correction.py предложил синхронные изменения 12 опорных суставов (предел |Δq| = 0.0027669522 рад); передняя поднятая пара осталась без команд. Реальное смещение тех же маркеров после новой прямой кинематики: без компенсации 0.349–0.455 мм, с компенсацией 0.000530–0.000865 мм.

**Важно:** маркеры привязаны к локальной системе голеней из исходных контактов. При конечном виртуальном приращении проверяется их мировое положение; ни повторный поиск контакта, ни динамический шаг mj_step не использовались. То есть отсутствие скольжения под реальными нагрузками ещё НЕ доказано.

## Обнаруженный риск для сервоприводов

В номинальном MuJoCo XML все суставы имеют диапазон ±π рад. Это НЕ измеренные аппаратные ограничения. В исходной позе B два сустава уже превышают более ранний исследовательский предел IK ±1.7 рад: motor31 = +1.7084106 рад, motor27 = −1.7084526 рад. Превышение каждого около 0.0084 рад, или 0.48 градуса. Следующий планировщик не должен путать пределы модельного XML с пределами физического робота.

Пять локальных интеграционных тестов PASS на реальных CAD30-данных; без восстановленного приватного CAD30 эти проверки SKIP, а не подменяются синтетическими.

## Как повторить

Необходим Python 3.13, MuJoCo 3.14.0, NumPy/SciPy и локальные приватные архивы:
- Модель: https://drive.google.com/file/d/1qN8KAgekhXm5RasMXSHNxHAsMxivpZ44/view — SHA-256 f2986c6256a19df59769db2ce0bdd9ea4cfee1ca36c27fb2d221da8c2a0afd53. XML: source/mjcf/scene_local30_nominal.xml.
- Состояние B: https://drive.google.com/file/d/15mcLT9KHRrxAnjSG7KTTCc02K6aBDJb1/view — SHA-256 dbc782200d58a78b811840c0af67fef52d8e7666d727f14d9ecc6d0d1727ca6e. В ZIP использовать results/claw_tuck_compare_2026-11-04.json (semi_tucked 9.3 s).
- Офлайн-окружение: Alfred-Runtime-Bundles/MuJoCo-3.14.0-cp313-linux-x64, SHA-256 архива 6d14d0c17294bac5436e1167ca4a97c30061da8efaa0a2b904c171bcac4a7b13.

~~~bash
export CAD30_MODEL_XML="$PWD/source/mjcf/scene_local30_nominal.xml"
export CAD30_REPLAY_ZIP="/path/to/FNK0052_claw_tuck_ABC_2026-11-04_v2_no_CAD.zip"
PYTHONPATH=experiments/cad30 python experiments/cad30/cad30_pose_b_jacobian_check.py --model "$CAD30_MODEL_XML" --replay-zip "$CAD30_REPLAY_ZIP" --out results/pose_b_jacobian_local.json
PYTHONPATH=experiments/cad30 python -m unittest -v test_cad30_pose_b_jacobian_check
~~~

## Чего не доказали

Нет свободной динамической эволюции от предыдущей позы к этой, реальных сил контакта/трения при исполнении команды, настоящей моторной модели или полного прогнозного цикла. Это удачное прохождение **кинематических ворот**, а не физическая верификация WBC/MPC.

Следующая проверка: перестроить исходную позу с запасом по действительно допустимым углам, затем выполнить серию таких малых корректировок с динамическим mj_step, силовой LP/QP-проверкой и запретом потери контакта.
