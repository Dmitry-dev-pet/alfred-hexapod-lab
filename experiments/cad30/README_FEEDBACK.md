# FNK0052: первый контактный контроллер, локальные эксперименты 2026-11-03

**Статус:** прототип сенсорной координации, не нейросеть, не реализация neuroWalknet, не откалиброванный цифровой двойник. Все эксперименты ниже выполнены непосредственно в Python/MuJoCo 3.14.0 ChatGPT (локальная вычислительная среда), GitHub Actions для вычисления не использовались.

## Физическая модель

Пиннованная MJCF-геометрия MattiaGrigoli, commit `5c9a84c16335b30036e451c691d2c544abf4bc72` с **30 из 32 оригинальных STL**, подтверждённых Git blob SHA. Обе недостающие сетки (`bigservo1.stl`, `topplate.stl`) заменены только в визуализации. Контакты шести голеней действительно построены из исходной `tibia.stl`, 20 приводов (18 ног + 2 головы). Распределение масс 1,644 / 1,804868 / 2,080 кг — **расчётные сценарии, не взвешенные детали**. Контроллер момента PID-упрощённый: PD `Kp=7`, `Kd=0.32`, жёсткий предел `±0.7 Н·м`, который НЕ является измеренным рабочим моментом сервопривода.

Источник CAD с условиями Freenove: https://github.com/MattiaGrigoli/autonomous_hexapod/blob/main/LICENSE-3RD-PARTY.md. Тяжёлые оригинальные STL остаются в приватном Drive, а не в GitHub.

## Алгоритм прототипа

Каждая нога имеет независимые состояния **опоры / переноса**, собственный таймер опоры и события реального контакта с поверхностью. Подъём разрешается только при положительном геометрическом запасе пяти оставшихся опор, если соседняя нога не переносится, тело не наклонено сверх установленного порога. После наблюдаемого касания возбуждается готовность соседних ног.

**Важные отличия от нейробиологии:** для безопасности установлен **глобальный запрет второго одновременного переноса**; возбуждение идёт по двусторонним соседям, а не по направленным правилам Cruse 1–3. Это лабораторная эвристика, вдохновлённая локальными правилами, но не Walknet и не neuroWalknet. Биологическая ориентация следующего шага: [Schilling et al., PLOS Computational Biology (2020)](https://pmc.ncbi.nlm.nih.gov/articles/PMC7205325/) и [Schilling et al. Walknet (2013)](https://pmc.ncbi.nlm.nih.gov/articles/PMC3755227/).

**Критическое исправление контакта:** для окончания переноса нужен отдельный IK-таргет постановки стопы. Абляция при массе 1.805 кг: без таргета — 4,47 см за 8 с и длительное зависание ноги; с таргетом и без дополнительного опускания — 10,02 см; с таргетом и запасом опускания 6 мм — 10,14 см. Таким образом, определяющим оказалось задание конечной позы, **не** запас в 6 мм.

## Сравнение при одинаковых параметрах

Все эксперименты на ровной поверхности, 8 секунд движения после 1 секунды стабилизации стойки, команда длины шага 35 мм, подъёма 20 мм, период 2.4 с, начальная масса 1.804868 кг (если не указано иное), одинаковый расчёт контактов MuJoCo. Код сохраняет 50-Гц сведения о реальных опорах и 9-Гц снимки положения суставов.

| Коэффициент трения (модель) | Походка | Продвижение (см) | Доля с менее чем 3 опорами | Минимум опор |
| --- | --- | ---: | ---: | ---: |
| 1.1 | Tripod | 11.92 | 0.00% | 3 |
| 1.1 | Волновая | 10.07 | 0.00% | 3 |
| 1.1 | Контактный прототип | 10.14 | 0.00% | 3 |
| 0.6 | Tripod | 12.01 | 6.98% | 1 |
| 0.6 | Волновая | 10.88 | 0.75% | 2 |
| 0.6 | Контактный прототип | 11.30 | 0.25% | 2 |
| 0.3 | Tripod | 11.37 | 3.99% | 0 |
| 0.3 | Волновая | 10.96 | 0.75% | 0 |
| 0.3 | Контактный прототип | 11.83 | 0.75% | 0 |

**Интерпретация:** при μ=0.6 контактный прототип реже теряет опору, чем tripod, но скорость немного ниже. При μ=0.3 **все три** контроллера иногда теряют контакт всеми ногами. Пройденная дистанция на скользком полу сама по себе не доказывает хорошую походку: tracking крайней точки `tibia.stl` показывает рост смещения во время фазы опоры в несколько раз. Эта метрика включает вращение/перекатывание CAD-голени, а не только чистое скольжение пятки.

При μ=1.1 контактная схема для массы 1.644 / 1.805 / 2.080 кг прошла 10.04 / 10.14 / 10.22 см. При 2.08 кг контроллер насыщал заданный момент 0.7 Н·м **1.125%** шагов; без реального torque-speed/power модели этот предел условен.

Отдельная абляция: задержка 100 мс между касанием и следующим подъёмом уменьшила продвижение при μ=1.1 с 10.14 до 8.80 см, но **не** избавила от кратковременной потери опоры на скользком полу. Поэтому пока не включаем её по умолчанию.

## Как воспроизвести

1. Из приватного Drive восстановить предыдущий архив CAD30 в каталог `experiments/cad30/` (`source/meshes`, `source/mjcf`, `hexlab` и `data` должны быть доступны рядом или из корня GitHub). Оригинальные CAD-файлы в GitHub не входят.
2. Установить Python 3.13, MuJoCo 3.14.0, NumPy, SciPy; скрипты эксперимента и postprocessing лежат в этой папке. При работе из корня GitHub убедиться, что модуль `hexlab` включён в `PYTHONPATH`.
3. Запустить тесты и опыты:

```bash
python -m unittest discover -s tests -v
python local_contact_gait.py --mass nominal --seconds 8
python local_contact_gait.py --mass lower --seconds 8
python local_contact_gait.py --mass upper --seconds 8
python local_contact_gait.py --mass nominal --seconds 8 --friction 0.6
python local_contact_gait.py --mass nominal --seconds 8 --friction 0.3
python local_contact_gait.py --mass nominal --seconds 8 --no-landing-target
python local_contact_gait.py --mass nominal --seconds 8 --landing-extension-mm 0
python local_contact_gait.py --mass nominal --seconds 8 --touchdown-dwell-ms 100
python create_feedback_receipt.py
# OpenGL+FFmpeg:
xvfb-run -a env MUJOCO_GL=glfw python -c "import render_cad30_gaits; print(render_cad30_gaits.run('contact','nominal'))"
```

Протокол `results/contact_feedback_cad30_comparison_2026-11-03.json` содержит **SHA-256** каждого использованного полного JSON-receipt и кода. Полная серия JSON, исходники, MP4/GIF — архив в Drive; только небольшой summary — в GitHub.
