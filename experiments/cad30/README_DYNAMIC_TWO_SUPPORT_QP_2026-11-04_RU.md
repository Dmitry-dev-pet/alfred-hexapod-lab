# CAD30: две реальные опоры → восстановление четырёх, MuJoCo 3.14 / Mink 1.4 / QP

**4 ноября 2026 года · исследовательский результат, НЕ походка и НЕ безопасный контроллер для Freenove.**

Связанные задачи: [#26 (прогнозирование)](https://github.com/Dmitry-dev-pet/alfred-hexapod-lab/issues/26), [PR #34 (один задний шаг с Mink)](https://github.com/Dmitry-dev-pet/alfred-hexapod-lab/pull/34), [PR #35 (отрицательный PD-тест двух опор)](https://github.com/Dmitry-dev-pet/alfred-hexapod-lab/pull/35). **Ни одна копия оригинальных CAD/STL не публикуется в GitHub.**

## Что действительно выполнено

На оригинальной модели Freenove FNK0052 CAD30 из личного Drive, со свободным корпусом, начальным физическим состоянием B после предварительной ребалансировки (архив PR #34) и **18 управляемыми сочленениями ног + 2 дополнительными приводами**:

1. Mink (готовая внешняя IK-библиотека) создал **шесть виртуальных малых смещений корпуса по 2 мм** при фиксированных на полу четырёх стопах. На всех узлах были проверены математические условия из предшествующего G2: статические силы, модельные ограничители суставов и возможность достигнуть целевых стоп. Это только план, не телепортация корпуса.
2. Независимая **непрерывная MuJoCo динамика с `mj_step=0.002` с**, обычные модельные PD приводные команды, выполняет эти целевые положения. Реальный центр масс от `y=-15,27 мм` смещается к `y=+0,14 мм` (на 15,4 мм). **В ходе подготовки несколько мгновений остаётся лишь две нагруженные ноги**, поэтому это не сертифицированный квазистатический переход 4→2.
3. В следующей фазе применяется **новый QP-оптимизатор полной мгновенной динамики**, который на каждом 10-мс обновлении решает `M(q)·qdd + h(q,qdot) = Sᵀτ + Jᵀf` совместно с ограничениями неотрицательных нормальных реакций, 16-фасетным вписанным конусом трения, ограниченными ускорениями корпуса/суставов и |τ|≤90% модельных пределов. В качестве гипотетических опор задаются **только `ml/mr`**, задние `bl/br` получают ограничения на положительное вертикальное ускорение стопы. Это **не полноценный MPC** и **не автоматический выбор контактов**.
4. Контроллер через `d.ctrl` действительно разгружает и **оторвает обе задние голени**, оставляя две средние как фактически нагруженные опоры. Критерий *реальной* двухопорной фазы одновременно требует: (`ml`,`mr`) Fz>0,08 Н; `bl`,`br` Fz<0,08 Н; у каждой задней стопы **нулевое число контактов геометрии tibia с полом**; её локальный маркер реального контакта поднят на ≥2 мм от собственного начального положения. Всё считается на **каждом физическом 2-мс шаге**, без подстановки командной маски.
5. Через **0,12 с запланированного QP** (до известной зоны невозможности продолжения) управление переключается на плавный 0,6-секундный возврат PD к ранее допустимой четырёхопорной позе, а затем 0,5 с физически удерживает её. Это **заранее заданный переключатель**, не MPC-план шагов, не автономный recovery policy.

Кратковременное поддержание двумя опорами не доказывает, что робот сможет двигаться и останавливаться таким образом при других состояниях, на скользком полу или на настоящих MG996R.

### Обязательные отрицательные контрольные прогоны

В точности та же схема с одной изменённой величиной, коэффициентом трения μ (и соответствующим ограничением QP):

| μ | Непрерывная проверенная двухопорная фаза | Последние 0,2 с: каждая Fz ≥0,2 Н | Итог |
|---:|---:|---:|---|
| 1.1 | 0,238 с | 100/100 | **PASS только для номинальной модели** |
| 0.8 | 0,258 с | 91/100 | **FAIL**: недостаточный резерв и эпизод менее 2 нагруженных опор |
| 0.6 | 0 с | 65/100 | **FAIL**: QP становится недопустимым; опоры теряются |
| 0.3 | 0 с | 77/100 | **FAIL**: QP становится недопустимым; опоры теряются |

У нижних μ симуляция не прерывает PD возврат при превышении предельного угла корпуса; это **отрицательная диагностическая запись**, не предлагаемый аварийный контроллер. В частности, в µ=0,6/0,3 наклон выходит далеко за приемлемую область — нельзя называть эти траектории устойчивыми.

## Математический разбор (отдельно от реальных опытов)

`instantaneous_support_lp.py` перечисляет 11 различных 4-, 3- и 2-опорных конфигураций при исходной скорректированной позе и после **виртуального** переноса на 2, 4, …, 12 мм вперёд. Это только *мгновенная линейная* задача: `qvel=0`, Jdot·qvel=0, гипотетические центры опор; предел ускорения суставов ±35 рад/с², ускорения линейные ±1 м/с², 90% моментов, требование положительного ускорения подъёма ≥0,5 м/с². Для пары **`ml/mr`** оптимизированное минимальное угловое ускорение по компонентам корпуса снижается так:

| Виртуальное перемещение корпуса | Требуемое минимальное по норме ∞ угловое ускорение |
|---:|---:|
| 0 мм | 21,76 рад/с² |
| 2 мм | 15,57 рад/с² |
| 4 мм | 10,83 рад/с² |
| 6 мм | 5,90 рад/с² |
| 8 мм | 0,76 рад/с² |
| 10 мм | 0 рад/с² |
| 12 мм | 0 рад/с² |

**Значение «0» — всего лишь наличие одного мгновенного LP решения**, а не возможность бесконечно стоять на двух ногах: в нём могут одновременно требоваться предельные суставные ускорения, расход момента, линейное ускорение корпуса и тангенциальные силы. Даже для численно допустимой конфигурации динамическое продолжение в MuJoCo может оказаться невозможным. При исходных параметрах в пяти других двухопорных парах эта ограниченная задача оказалась недопустимой; общий физический запрет из этого не следует.

## Исходники, испытания, повторяемость

Зависимости Python 3.13, MuJoCo 3.14, Mink 1.4, qpsolvers 4.13, DAQP 0.11, SciPy, NumPy. Готовые проверенные offline-зависимости размещены в личном Drive в `Alfred-Runtime-Bundles`.

```bash
export CAD30_MODEL_XML=/absolute/path/to/scene_local30_nominal.xml
export CAD30_SAFE_STATE=/absolute/path/to/cad30_safe_pose_B_nominal.json
export PYTHONPATH=experiments/cad30
python experiments/cad30/two_support_transfer.py \
  --model "$CAD30_MODEL_XML" --state "$CAD30_SAFE_STATE" \
  --mu 1.1 --qp-duration 0.12 --return-mm 0 \
  --out /tmp/two-support.json
python experiments/cad30/instantaneous_support_lp.py \
  --model "$CAD30_MODEL_XML" --state "$CAD30_SAFE_STATE" \
  --output /tmp/contact-lp.json
python -m unittest discover -s tests -p test_two_support_transfer.py -v
```

Если приватные CAD XML/модели недоступны, **интеграционные тесты SKIP**, а не выдают синтетический PASS.
