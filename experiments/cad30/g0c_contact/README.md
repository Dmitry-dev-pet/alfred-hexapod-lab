# CAD30 G0c — калибровка дискретных контактов Drake и аудит ограничений IDTO

Дата: 5 ноября 2026. Источники: [Issue #50](https://github.com/Dmitry-dev-pet/alfred-hexapod-lab/issues/50), [G0b PR #58](https://github.com/Dmitry-dev-pet/alfred-hexapod-lab/pull/58), [IDTO-CAD30 PR #57](https://github.com/Dmitry-dev-pet/alfred-hexapod-lab/pull/57). **Статус: два локальных состояния — частичная калибровка; полная gait НЕ получена, hard torque constraints в оригинальном IDTO отсутствуют.** Без изменения `main`, без физических команд роботу, без GitHub Actions как вычислителя.

## На чём выполнено

- Исходный Freenove FNK0052 CAD30 (оригинальные 30 STL в приватном Google Drive), Drake 1.30.0 и MuJoCo 3.14.0. Сравнивались **одни и те же реальные сохранённые** шестиопорное и четырёхопорное состояния из PR #40.
- Копия CAD30 для Drake с оригинальными collision-мешами голеней и **конечным box-полом** из PR #57; оригинальный MuJoCo XML не изменялся.
- Независимый Drake C++ `MultibodyPlant(time_step=0.002)`, восстановленная инерция роторов `0.002` и ограничители приводов **в метаданных**, 20 дискретных шагов по 2 мс с фиксированным исходным вектором PD-моментов (без контроллера перепланирования).
- Перебор `penetration_allowance` в диапазоне 1 мм — 0,04 мм, затем уточнение 0,04–0,06 мм. Это **контактная модель Drake plant**, а не внутренние контактные функции оптимизатора IDTO.
- Сопоставление с зафиксированными силами MuJoCo *с тем же конечным box-полом* из PR #58; отдельно выполнен контроль MuJoCo 2–40 мс. Там также использован фиксированный первоначальный PD-момент.

## Результат контактов

| `penetration_allowance` | Drake 6 опор Fz (2 мс) | Drake 4 опоры Fz (2 мс) | Минимум реальных нагруженных ног за 40 мс при 4 опорах |
|---:|---:|---:|---:|
| 1,000 мм | 2,755 Н | 2,496 Н | 3 |
| 0,060 мм | 17,471 Н | 17,050 Н | **3**, один провал на такте 6 (12 мс) |
| **0,055 мм** | **17,742 Н** | **17,345 Н** | **4/4 на всех 20 тактах** |
| 0,050 мм | 18,004 Н | 17,633 Н | 4 |
| 0,040 мм | 18,484 Н | 18,171 Н | 4 |
| **MuJoCo box (2 мс)** | **17,560 Н** | **17,274 Н** | 4 в отдельном 40-мс прогоне |

При δ=0,055 мм последние измеренные силы Drake к 40 мс — **17,702 Н** и **17,712 Н** соответственно. Для MuJoCo при той же фиксированной команде в 40 мс: примерно **17,576 Н** и **17,314 Н**. При default δ=1 мм реакция Drake в первые миллисекунды почти отсутствует, затем возникает существенный transient (до ~24 Н), корпус проседает до ~1,2–1,4 мм, и в 4-опорном случае к концу испытания осталось лишь 3 действительно нагруженных опоры. При δ=0,055 мм вертикальная просадка ~0,09–0,10 мм.

**Важно:** δ=0,055 мм — экспериментальный кандидат, *не* проверенная универсальная физическая эквивалентность. По отдельным ногам различия остаются, модели дискретного контакта различаются, геометрия MuJoCo может иметь два контактных пункта на голень против одного closest point Drake; движение/удары/скольжение не проверены. Нельзя выбирать δ по суммарной Fz и объявлять походку. Полный численный отчёт — `results/G0C_COMPACT_RESULTS_20261105.json`.

## IDTO имеет ещё одну, независимую модель контакта

Pinned Toyota Research Institute IDTO `de0629c7811aa9b330e56c4385629005b09495f0`, `optimizer/trajectory_optimizer.cc`, функция `CalcContactForceContribution`, применяет сглаженную нормальную силу для неподвижных контактов:

\[
F_n(d)=k\sigma\ln(1+e^{-d/\sigma})
\]

Для наших параметров smoke YAML `k=2000 Н/м`, `σ=0.01 м`, нулевая нормальная скорость:

| Зазор голень–пол | Расчётная «контактная» сила IDTO |
|---|---:|
| 0 мм | 13,863 Н |
| +2 мм | 11,963 Н |
| +20 мм | **2,539 Н** |

Это **сглаженная суррогатная сила при ненулевом зазоре**, а не физический контакт: проверка `>=3 actual loaded feet` внутри исходной задачи **не заложена**. Более жёсткая настройка дискретной физики Drake автоматически не исправляет контактную модель IDTO. Нужен отдельный bounded study параметров `k,σ`, проверка геометрической clearance, комплементарности и настоящих Fz при независимом MuJoCo replay. Скрывать «виртуальные опоры» нельзя.

## Жёсткие пределы моментов IDTO

В `optimizer/problem_definition.h` pinned IDTO усилия входят в **мягкий квадратный штраф** `τᵀRτ`, но нет явного box-ограничения ±0,7 Н·м. `effort_limit()` у Drake actuator также сам по себе не ограничивает управляющую силу. Прямой экспорт прежней короткой IDTO-траектории из PR #57 показал максимальные по времени обобщённые моменты:

- **18 приводов ног:** максимум **0,363948 Н·м** при модельном пределе 0,7;
- **2 привода головы:** максимум **0,009508 Н·м** при модельном пределе 0,2;
- **состояние решателя:** `Maximum iterations reached` (это не доказанная сходимость).

Новый скрипт `calibration_audit.py` делает **fail-closed ex-post gate** по всем 26 компонентам вектора максимальных обобщённых сил (6 неуправляемых + 18 ног + 2 головы), не выдавая прохождение за сертифицированную выполнимость. Негативные тесты специально отклоняют превышение на ноге либо голове. Реализация **hard inequality constraints внутри оптимизатора IDTO ещё не выполнена**; альтернатива — существующий Drake direct collocation/multiple shooting с явными ограничениями сил и контактов.

## Воспроизводимость

Потребуются *собственные* исходная сцена CAD30/Drake с оригинальными мешами, saved 6/4 физические q/v/u из PR #58, pinned Drake C++ 1.30, MuJoCo 3.14, NumPy для независимого MuJoCo скрипта (не включён в публичный bundle с приватными именами состояний).

```bash
cmake -S . -B build -Ddrake_DIR=/path/to/drake/lib/cmake/drake
cmake --build build -j2
python run_contact_matrix.py \
  --probe ./build/drake_contact_probe \
  --scene /private/Drake-CAD30/scene.xml \
  --six-input /private/six_q_v_u.txt \
  --four-input /private/four_q_v_u.txt \
  --g0b-receipt /path/to/G0B_CONTACT_ACTUATOR_RECEIPT.json \
  --out-dir /private/new-contact-calibration
python calibration_audit.py \
  --refined /private/new-contact-calibration/refined_calibration_private.json \
  --baseline /path/to/G0B_CONTACT_ACTUATOR_RECEIPT.json \
  --mujoco-temporal /private/mujoco_temporal.json \
  --idto-stdout /private/idto_60_iter_stdout.log \
  --out results/G0C_COMPACT_RESULTS_20261105.json
python -m unittest -v test_calibration_audit
```

**Проверки:** реальный C++ компилируется в окружении Drake 1.30, 10/10 unit-тестов Python PASS, 10 независимых физических 40-мс прогонов для δ=0,04–0,06 мм (два сохранённых состояния × пять δ), плюс coarse-sweep на более мягких контактах. Неполное/повреждённое описание временного ряда и превышение модельного момента отклоняются тестами. Исходные XML/STL/OBJ, qpos/qvel и сырые stdout/stderr остаются только в личном Google Drive. В GitHub — исходники, критерии, компактный JSON и хеши.

## Следующий физический критерий

1. Прогнать подтверждённые *движущиеся* позы и реальное разгружение/приземление одной ноги в двух средах. Сравнивать по Fz каждой ноги, контактным событиям, вертикальному дрейфу, а не только сумме Fz.
2. Для G1 решить период с **жёсткими** torque/контактными ограничениями. Пока IDTO оставляет только мягкую стоимость, ограничиться post-hoc отрицательным/положительным фильтром и честным `HARD_TORQUE_NOT_IMPLEMENTED`.
3. Только замкнутый период, достигаемый из исходной шестиопорной стойки, проверить ≥3 раза подряд в MuJoCo с полным учётом подготовительного перемещения. Не объявлять текущие 40 мс стойки походкой.
