# CAD30: физический подбор команд перед подъёмом средней ноги (5 ноября 2026)

**Статус: один физически подтверждённый подъём → перенос → приземление `ml` с тремя реально нагруженными опорами. НЕ полная четырёхногая походка.** Изменений настоящего Freenove нет. `main` не трогаем, PR — draft, никаких merge без владельца.

Связано с [Issue #38](https://github.com/Dmitry-dev-pet/alfred-hexapod-lab/issues/38), исходным [Pupper baseline PR #40](https://github.com/Dmitry-dev-pet/alfred-hexapod-lab/pull/40), [218 математическими узлами PR #43](https://github.com/Dmitry-dev-pet/alfred-hexapod-lab/pull/43), отрицательными [10 физическими прогонами PR #44](https://github.com/Dmitry-dev-pet/alfred-hexapod-lab/pull/44).

## Что поменяли по сравнению с прежней математикой

Раньше мы решали обратную кинематику и статическую LP для **заданных** точек контакта, а затем отдавали 218 команд углов PD-контроллеру. В физических прогонах вместо разгрузки `ml` теряла опору `br`, хотя математические силы были допустимы.

Здесь оптимизируем **входы того самого реального для симуляции PD-контроллера** через независимые прямые MuJoCo rollouts:

1. Берём `qpos/qvel` и действительно нагруженные `mr/bl/br/ml` из последнего 2-мс кадра перед `ml` (узел 117, PR #44); никакой новой искусственной позы.
2. SciPy SLSQP находит минимальный целевой сдвиг COM внутрь **измеренного** треугольника `mr/bl/br` с заданным запасом. Уже на следующем этапе не считаем, что этот сдвиг получится автоматически.
3. Через прежнюю проверенную CAD30 IK получаем положения суставов, которые удерживают 4 стопы в их мировых координатах при целевом перемещении корпуса. Подаём **только моторные углы** через исходный PD (`Kp=7`, `Kd=.32`, ограничение исследования ±0.7 Н·м), корпус MuJoCo свободен.
4. В том же физическом состоянии вычисляем swing-цель `ml` (движение вперёд и вверх), снова командуем **только три сустава `ml`**. Остальные приводные цели удерживают реальную тройку.
5. В `mujoco.mj_step(dt=0.002 s)` измеряем **каждые 2 мс** `Fz` по именам tibia, фактический COM и его запас относительно треугольника, реальные контакты, углы, момент и мировое смещение. Mesh clearance измеряем на подвыборке каждые 20 мс. `d.qpos[:7]` **не меняем после инициализации**.
6. `scipy.optimize.differential_evolution` перебирает 3 параметра команды: желаемый статический запас COM, запрошенный шаг стопы и высоту swing. Считаем критерий по **реальной** физике, а не по идеальным LP-силам. Вето, если одна из `mr/bl/br` разгрузилась (`Fz < 0.2 Н`), трёхопорный запас в swing меньше 10 мм, не было mesh-clearance ≥2 мм с отсутствующим контактом в течение как минимум 0.25 с, не подтверждено touchdown всех 4 или превышены предварительные ограничения. Дополнительно штрафуем большую ошибку IK и перемещение опорных маркеров.

Это **physics-in-the-loop shooting optimizer для одного шага**, не full MPC, не контактно-неявное планирование, не аппаратный регулятор момента. Он использует измеренные силы MuJoCo для **оценки** траекторий. Непрерывной online force-feedback коррекции во время выполнения пока нет. Критерии в экспериментальных rollout регистрируют отказ, но не обеспечивают аппаратный emergency stop.

### Независимое непрерывное воспроизведение

От физически сохранённой **шестиногой** Pupper-стойки из PR #40 повторено **17 675 реальных 2-мс шагов** по оригинальному старому плану до узла 117, без промежуточных `qpos`-телепортаций и без reset корпуса. До этого узла всегда оставалось ≥3 действительно нагруженных ноги; отмечаем, что на некоторых подготовительных фазах схема из 5 предполагаемых опор не выполнялась, и **это не аппаратная гарантия**.

**В том же самом `MjData`** затем выполнена найденная оптимизатором подготовка и `ml` swing, с точным повторением положительного локального результата. После приземления все 4 снова несут нагрузку. Это теперь **одна непрерывная физическая цепочка от сохранённой шестиногой стойки до одного среднего шага**, но не полный четырёхшаговый crawl.

**Продвижения корпуса пока НЕТ:** за предварительную старую подготовку корень уходит на **−73.819 мм** от сохранённой шестиногой стойки, ещё примерно −29 мм — за перенос веса и swing. Итог около **−103 мм**, хотя сама `ml` делает +21 мм вперёд. Старый математический cycle ещё не был завершён. Дальше нужно научить робота возвращать COM вперёд и делать последовательно `mr`, `bl`, `br` с подтверждёнными touchdown, а затем повторять циклы. Нельзя маскировать задний ход предварительной подготовки.

## Репликация

Нужны Python 3.13, MuJoCo 3.14.0, Mink (для существующего Pupper baseline), NumPy, SciPy, DAQP, собственный модуль `hexlab`, оригинальный MJCF + 30 mesh в локальной файловой системе. В private Drive хранятся исходные архивы [CAD30](https://drive.google.com/drive/folders/1uPhhIjZApoDhjp2YEUPIc7osXoYYyfk_), [Pupper-6 snapshot](https://drive.google.com/file/d/1wx8j9HSrGwRLigg2rWCWPOyJZyFifHTn/view?usp=drivesdk), [math 218 trace](https://drive.google.com/file/d/1V_3qD8WTQgfqNZAEE11VBCe85gCpW0L1/view?usp=drivesdk), [old negative 2ms physics trace](https://drive.google.com/file/d/18ZICZjp2Y9xYKtxFz4dVw9hkDvLrzRKl/view?usp=drivesdk). Архивы требуют отдельной локальной распаковки, path подставляется по окружению.

```bash
export CAD30_ROOT=/path/to/private/cad30
export HEXAPOD_MATH_TRACE=/path/to/math_first_four_crawl_trace.json
export HEXAPOD_PHYSICS_TRACE=/path/to/dynamic_min3_03_trace_2ms.json.gz
export PUPPER_SIX_STATE=/path/to/pupper_stance_prebalance_35mm.json
export HEXAPOD_REPO_ROOT=/path/to/alfred-hexapod-lab

python experiments/cad30/contact_optimization/contact_aware_shooting.py \
  --cad-root "$CAD30_ROOT" --repo-root "$HEXAPOD_REPO_ROOT" \
  --math-trace "$HEXAPOD_MATH_TRACE" --physical-trace "$HEXAPOD_PHYSICS_TRACE" \
  --maxiter 1 --mu 1.1 --out /tmp/optimized_local_ml.json

python experiments/cad30/contact_optimization/replay_six_to_ml.py \
  --cad-root "$CAD30_ROOT" --repo-root "$HEXAPOD_REPO_ROOT" \
  --math-trace "$HEXAPOD_MATH_TRACE" --physical-trace "$HEXAPOD_PHYSICS_TRACE" \
  --six-state "$PUPPER_SIX_STATE" --optimized-summary /tmp/optimized_local_ml.json \
  --out /tmp/continuous_six_to_ml.json

python -m unittest discover -s experiments/cad30/contact_optimization -p 'test_*.py' -v
```

4 самостоятельных теста работают без приватного CAD. 2 интеграционных теста физически выполнены (μ=1.1 PASS, μ=0.6 ожидаемый FAIL как negative control), но **SKIP**, если приватный архив отсутствует.

## Проблемы и границы результата

- 18 позиционных приводов + 2 неизменных привода головы; здесь нет аппаратного канала измерения `Fz`, используются исключительно силы MuJoCo. Настоящий робот пока не исполнялся.
- Часть концевой траектории содержит допуск IK порядка 0.523 мм и нет проверенных реальных MG996R характеристик. Моторные и кинематические лимиты **условные**.
- Одна рабочая комбинация начальных условий не доказывает устойчивость к ошибкам массы, неверным коэффициентам трения, люфтам, меняющемуся контакту или неровному полу.
- Даже при успехе `ml` движется вперёд только одна стопа; корпус после подготовки находится позади исходного положения, поэтому **четырёхногой локомоции и повторяемых циклов нет**.
- Функция оптимизации содержит физические ограничения и negative controls, но **не является формальной гарантией безопасности**, особенно при изменении состояния или режимов опоры.

**Следующий небольшой эксперимент:** после подтверждённого touchdown `ml` автоматически пересчитать опорный треугольник и следующий шаг (`mr`), не сбрасывая `qpos/qvel`; подбирать команды по фактическим контактам тем же физическим решателем, проверять реальный forward COM и лишь затем переходить к четырём шагам, трём циклам и аппаратным датчикам.
