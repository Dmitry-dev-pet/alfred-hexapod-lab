# CAD30: физический третий шаг `bl` — условный успех, **не циклическая походка** (2026-11-05)

## Суть

Продолжение [PR #49](https://github.com/Dmitry-dev-pet/alfred-hexapod-lab/pull/49), [#47](https://github.com/Dmitry-dev-pet/alfred-hexapod-lab/pull/47), [#45](https://github.com/Dmitry-dev-pet/alfred-hexapod-lab/pull/45) и задачи [#38](https://github.com/Dmitry-dev-pet/alfred-hexapod-lab/issues/38). **Не сливать без отдельного ревью.** Ни одно испытание не управляет реальным Freenove. Оригинальные STL не находятся в GitHub или публикуемых исходных файлах.

Условия: оригинальная CAD30 (30 STL Freenove, восстановлены из личного Drive); MuJoCo 3.14, шаг физики 2 мс, модельная масса ≈1,805 кг, μ=1.1, PD Kp=7/Kd=0.32, пределы `|q|`≤1.7 рад и `|τ|`≤0.7 Н·м — **исследовательские гипотезы, не паспортные характеристики**. Силы по каждому контакту tibia измеряются внутри MuJoCo. Сохранённая начальная шестиопорная поза — уже после более ранней шестиопорной prebalance из PR #40, а **не** самый первоначальный стоящий робот.

## Непрерывный MuJoCo rollout (один MjData)

|---|---:|---|

| `ml` | +21,286 мм | проходящий физический локальный шаг |

| **Дополнительная перестановка `ml` назад** | **−84,966 мм** | проходящий **подготовительный**, но не поступательный перенос |
| `bl` | **+32,107 мм** | проходящий физический локальный шаг |

Для последнего `bl`: тройка **`ml/mr/br`** оставалась нагруженной с Fz ≥1,657 Н при каждом 2-мс такте переноса, минимальный реальный COM-margin **+16,036 мм**; 0 тактов потери нужной тройки; максимум `|q|` 1,636 рад, пик PD τ 0,467 Н·м; выдержка после приземления — 100% отсчётов с четырьмя нагруженными ногами. Лапа реально находилась в воздухе, без подмены qpos корпуса. Контроллер `MR` использует контактную обратную связь из PR #49. `ML`-перестановка реализуется теми же стандартными совместимыми IK+PD, с подписанным отрицательным смещением по мировой Y.

**Отрицательный net progress:** COM остаётся на **−67,511 мм** относительно сохранённой шестиногой начальной позы (после её предыдущей prebalance). До полезной повторяемой ходьбы ещё далеко. Переупорядоченный ход `ML` назад нельзя скрывать из оценки продвижения.

## Что мешает поднять четвёртую `br`

По финальному физическому snapshot после `bl` проекция COM находится за пределами треугольника `ml/mr/bl`: исходный signed margin **−48,327 мм**. При фиксированных стопах нужен минимум **69,234 мм** переноса COM в XY (−53,593 мм X, +43,830 мм Y) для условного запаса 10 мм. Этот результат — **только геометрическое необходимое условие**, а не достижимое движение.

Проверено несколько реальных локальных кандидатов `br` как после `bl`, так и при перестановке порядка задних шагов. Нулевых провалов нужных опор при соблюдении всех пределов не получено: геометрия/контакт/момент/суставные ограничения не проходят одновременно. **Не доказана общая невозможность** — не исследованы все варианты foothold и сопряжённых движений корпуса.

Подготовительный поиск:
- Перенос корпуса при неподвижных стопах для `bl` позволял поднять ногу, но сустав задней правой доходил до ~1,78 рад (выше условного 1,7), поэтому FAIL.
- Перенос `ml` назад на 75–100 мм позволил `bl` шагнуть вперёд; для robust baseline выбраны 85 мм (запас лучше, чем у 75 мм).
- Простое удлинение обратной связи PD, смена момента и уменьшение clearance не решили `br`.

## Воспроизведение

```bash
python -m unittest discover -s experiments/cad30/rear_crawl -p 'test_third_bl.py' -v
python experiments/cad30/rear_crawl/continuous_third_bl.py \
  --cad-root /path/to/private/cad30 \
  --repo-root /path/to/alfred-hexapod-lab \
  --six-file /path/to/pupper_stance_prebalance_35mm.json \
  --math-trace /path/to/math_first_four_crawl_trace.json \
  --negative-physics-trace /path/to/dynamic_min3_03_trace_2ms.json.gz \
  --optimized-ml /path/to/optimized_local_ml_20261105.json \
  --out-dir /path/to/output --raw
```

`continuous_third_bl.py` импортирует существующие `contact_aware_shooting`, `replay_six_to_ml`, `mr_contact_continuation` **из предыдущих draft PR**, а `lateral_foot_trial.py` — его минимальное локальное расширение. `--raw` пишет 2-мс реальные qpos/qvel/Fz; при выключенном флаге не создаёт их. Запускаем без Docker и без GitHub Actions на самой среде модели.

Результат и исходное физическое состояние — `results/continuous_third_bl_summary.json` / `results/after_bl_physical_state.json`; полные трассы и входные закрытые записи — на Google Drive, с SHA256 в отчёте и манифесте. `tests` без личной CAD проверяют **контракт результата**, а не заменяют реальное повторное моделирование.

Следующий шаг — перепланировать размещение **всех четырёх стоп и корпус** с учётом конечной доступности `br`, чтобы не приходилось возвращать `ml` назад на 85 мм. Строгие гейты ≥3 нужных нагрузок каждый 2-мс шаг, margin≥10 мм, Fz≥0.2Н, caps и положительное **полное** net-перемещение сохранять. Только завершённый повторяемый цикл можно называть походкой.
