# CAD30: 2, 3 и 4 опоры — контролируемый негативный baseline (2026-11-04)

**Статус: двухопорное движение НЕ продемонстрировано.** Этот опыт не является четырёхногой походкой, не является MPC и не доказывает невозможность двухопорной ходьбы на Freenove. Он проверяет лишь способность текущего ограниченного PD-управления разгрузить заданные ноги без телепортации корпуса.

## Постановка

Одна и та же ранее записанная физически полученная стойка B после коррекции из проекта (четыре несущие ноги `ml/mr/bl/br`, подняты передние `fl/fr`), исходный XML/30 CAD STL из приватного архива, масса 1.8048682 кг. В каждом независимом испытании: 0.3 с удержания, 0.7 с плавного подъёма **5 мм по IK** выбранных стоп, 0.4 с удержания, 0.7 с плавного возврата, 0.3 с финального удержания. Свободный корпус, `mj_step` 2 мс, PD `Kp=7, Kd=0.32`, условный лимит приводов 0.7 Н·м, трение μ=1.1. Состояния и фактические вертикальные реакции на *каждом* шаге; нагружена нога при `Fz > 0.08 Н`. Отдельные точки контакта одной и той же голени суммируются **по ноге**. Никаких поставленных видео.

## Фактические результаты

| Режим | Команда на подъём | Совпадение с заданными опорами (из 200 шагов) | Два контакта за весь опыт | Макс. наклон |
|---|---|---:|---:|---:|
| `four` | нет | 200/200 | 0/1200 | 2.56° |
| `three_rear_bl` | bl | 200/200 | 0/1200 | 2.58° |
| `three_middle_ml` | ml | 0/200 | 0/1200 | 3.47° |
| `two_middles_ml_mr` | ml, mr | 0/200 | 0/1200 | 3.96° |
| `two_rears_bl_br` | bl, br | 0/200 | 0/1200 | 2.51° |
| `two_left_ml_bl` | ml, bl | 0/200 | 0/1200 | 2.66° |
| `two_right_mr_br` | mr, br | 0/200 | 0/1200 | 2.66° |
| `two_diag_ml_br` | ml, br | 0/200 | 0/1200 | 3.47° |
| `two_diag_mr_bl` | mr, bl | 0/200 | 0/1200 | 3.48° |


Задняя левая `bl` действительно разгрузилась при одиночной команде — 200 из 200 физических шагов в фазе 0.4-секундного удержания; три другие ноги сохранили нагрузку, максимальный наклон ~2.58°, насыщения модельного момента нет. В **шести вариантах** команды на одновременный подъём двух ног не удалось получить *ни одной* двухопорной фазы по измеренным `Fz` (0 из 1200 шагов в каждом варианте). Иногда не разгружалась ни одна нога, иногда лишь одна — например, при подъёме `ml+br` реально разгрузилась только `br`.

**Критический контроль:** команда поднять среднюю `ml` оказалась обманчива: фактически оставалась нагружена `ml`, зато разгрузилась другая — задняя правая `br` (все 200 шагов фазы удержания). Поэтому понижение числа контактов само по себе **не свидетельствует об исполнении правильной команды**. Надо проверять имена опор и запас сил, а не только число.

Максимальный фактический наклон во всех девяти коротких прогонах не превысил 4°, отсутствие падения за 2.4 с не означает устойчивую динамическую походку. В сценарии `bl+br` исследовательский угловой лимит ±1.7 рад кратковременно нарушен (~1.704 рад), этот вариант не проходит hardware-style gate. Неизвестны реальные MG996R характеристики, friction/масса/датчики, нет повторов или возмущений.

## Почему это важно

Исходный IDTO Mini Cheetah успешно находит двухопорную динамику благодаря MPC и другой механике. В нашей CAD30-модели текущая PD-команда подъёма ног автоматически меняет нагрузки и **не контролирует контактный режим**. Для двух опор необходим отдельный динамический контактно-неявный / заданный план с контролем инерционных моментов, `q/qdot`, будущих состояний, ограничений двигателей, фактической разгрузки, повторной постановки и возможности остановиться. Статический COM-многоугольник с двумя опорами не определён; двухопорные периоды нужно оценивать по динамике и жизнеспособности следующего состояния, а не требовать COM внутри треугольника.

**Следующий проектный шаг:** в #26 сохранить 3-опорный режим как контрольный baseline, отдельно разрешить *исследовательский* двухопорный кандидат с модельным MPC/контактным оптимизатором, обязательной проверкой реальных реакций и ограничений в MuJoCo. Не выполнять реальные команды на аппаратном роботе, не объявлять полный цикл до четырёх настоящих liftoff/touchdown и доказанного продвижения. Главная ветка остаётся неизменной.

```bash

  --model source/mjcf/scene_local30_nominal.xml \
  --state results/cad30_safe_pose_B_nominal.json \
  --outdir /tmp/cad30_2_3_4
```
