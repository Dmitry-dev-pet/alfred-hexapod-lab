# CAD30 / G1 — периодическая траектория: независимая обратная динамика и подготовка IDTO

**Статус: `G1_NOT_SOLVED / IDTO_MULTIPHASE_NOT_RUN / SAMPLED_INVERSE_DYNAMICS_SCREEN_ONLY`.** Работа по [Issue #50](https://github.com/Dmitry-dev-pet/alfred-hexapod-lab/issues/50), поверх протокола [PR #53](https://github.com/Dmitry-dev-pet/alfred-hexapod-lab/pull/53). Выполнена в отдельной вычислительной среде 5 ноября 2026. **Никакого доказательства реальной ходьбы или невозможности ходьбы нет.**

## Что именно сделано

1. Из сохранённого `math_first_four_crawl_trace.json` [PR #43](https://github.com/Dmitry-dev-pet/alfred-hexapod-lab/pull/43) построена единая **плановая** четырёхшаговая траектория: исходный узел **106** (виртуальная четырёхопорная стойка после подготовки), конечный узел **217** (виртуальное геометрическое замыкание), 29 интерполированно выбранных узлов, `ML→MR→BL→BR`, заданный прирост root world-Y **20 мм**, отличие 18 углов суставов на концах `≤6.5×10⁻⁸ рад`. Это исходный математический кандидат PR43, **не найденная сейчас новая физическая походка**. Он не подтверждён как физически достижимый после шестиопорной подготовки.
2. Создан **не проверенный компиляцией** опциональный адаптер к *локальной копии* pinned Toyota IDTO: `generate_reference.py` создаёт полный временной `q_nom[0..T]`; `patch_local_idto.py` добавляет чтение этого массива и запись решений. Ядро оптимизатора не меняется. Две попытки пересборки C++-модуля `examples/example_base.cc.o` прервались по лимиту выполнения, то есть **full-period IDTO не выполнялся**. Перед выполнением `patch_local_idto.py` явно сохраняет копию исходного файла. Исходный IDTO в рабочем каталоге восстановлен.
3. Проведён **отдельный тест необходимого условия** на всех **218** виртуальных положениях, включая математическую шестиопорную подготовку. Для `q(t)`, полученных конечной разностью с разными равномерными шагами, вычислялись `M(q) q̈ + h(q,q̇) − qfrc_passive`, реальные MuJoCo Jacobians CAD30 в модельных дистальных точках tibia и решалась линейная задача по нормальным/касательным силам и моторным моментам с точечно-контактной ромбической аппроксимацией трения. **Это не `mj_step` и не настоящие реакции MuJoCo контактов.**

## Почему математическая возможность и физическое движение расходятся

Сохранённый PR #43 уже проходил статические IK/LP-проверки; PR #44 показал **0/10 завершённых физических циклов** при честной свободной MuJoCo динамике и PD-приводах. Нынешняя проверка добавила приближение требуемых инерционных сил при разных скоростях. Даже LP-PASS во всех узлах недостаточно, потому что:

- положения стоп и контактные режимы *назначены* в математической траектории; нет доказательства фактических `Fz`, удара/приземления, отсутствия отрыва другой стопы, коллизий или проскальзывания;
- конечные разности с одинаковым dt создают резкие изменения скоростей/ускорений на границах фаз, не моделируют импульсные силы;
- LP допускает произвольные моментные воздействия, в то время как реальные позиционные сервоприводы через PD могут не воспроизвести их;
- нет жёсткого замыкания `q,qdot,contact mode` после *реального* цикла или воспроизведения ≥3 циклов в одном `MjData`;
- начальная 4-опорная стойка для части плановой траектории математическая, **не достигнута физически** в этом эксперименте.

## Воспроизведение

Из собственного приватного Drive восстановить оригинальные 30 CAD STL и их MuJoCo сцену, архив математического следа PR43. Для Python 3.13 нужны `mujoco==3.14.0`, NumPy, SciPy, существующий `hexlab/stand_geometry_v04.py`.

```sh
# Тесты генератора и отчёта (интеграционные тесты пропускаются без приватных входов)
CAD30_MATH_TRACE_ZIP=/private/math-trace.zip python -m unittest -v test_g1_reference.py

# Все 218 узлов: моментно-контактная LP, не физический rollout
PYTHONPATH=/path/to/CAD30-source python inverse_dynamics_gate.py \
  --model /private/CAD30/source/mjcf/scene_local30_nominal.xml \
  --zip /private/math-trace.zip --dt .06 --out /private/trace_0p06.json

# Генератор 29-узлового номинального периода для будущего IDTO
python generate_reference.py --trace-zip /private/math-trace.zip \
  --out /private/periodic_nominal --steps 28 --dt .1 --iters 25
```

Адаптер для IDTO **не исполнять как подтверждённый рабочий**: `patch_local_idto.py` — непроверенная компиляцией подготовка. Следующее действие — ускорить/изолировать C++-сборку, выполнить IDTO с 4 фазами и жёстко проверить его outputs, а если hard-contact/periodicity не реализуемы в IDTO — использовать уже имеющиеся фазовые direct multiple shooting / collocation возможности Drake. Подмена мягкой стоимости полноценной связанной оптимизацией запрещена.
