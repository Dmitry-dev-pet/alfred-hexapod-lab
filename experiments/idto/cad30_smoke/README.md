# CAD30 → Drake / TRI IDTO: исполняемый короткий эксперимент (2026-11-05)

**Статус: `IDTO_NATIVE_CAD30_OPTIMIZER_RUN_PASS_NOT_GAIT`.** Это не MPC-походка, не повторяемый цикл и не точная копия контакта MuJoCo. Основная задача — [Issue #50](https://github.com/Dmitry-dev-pet/alfred-hexapod-lab/issues/50), критерии целого периода — [PR #53](https://github.com/Dmitry-dev-pet/alfred-hexapod-lab/pull/53).

## Что действительно удалось

1. Перенесён исходный Freenove CAD30 **без повторного определения масс/суставов** в Drake 1.30.0, проверена ранее рассчитанная кинематико-инерционная parity с MuJoCo. Исходные частные CAD/30 STL — только в личном Drive, ни один бинарный файл не публикуется.
2. Собран нативный upstream [Toyota Research Institute IDTO](https://github.com/ToyotaResearchInstitute/idto) `de0629c7811aa9b330e56c4385629005b09495f0` с отдельным `cad30_idto_smoke`-адаптером. Сборка Clang++ `-O0 -g0` успешна, запускается в Linux amd64. Для линковки понадобились путь к `libgflags` в изолированном Ubuntu Jammy sysroot и **патч только вывода диагностических векторов** из-за различий системного Eigen и Drake binary (`diag_format_compat.patch`). Оптимизационное ядро IDTO не изменено.
3. Прямая модель с выпуклыми сетками ножек выдаёт **исключение Drake 1.30**: `Signed distance queries between shapes 'Convex' and 'Halfspace' are not supported ...`. Это ограничение вызова contact-distance API, не доказательство невозможности походки.
4. Для **диагностического, отдельного** запуска контакты шести тибий заменены на сферы радиусом **4 мм** с центрами на CAD-ориентирах концов ножек; не участвующая в столкновениях визуальная/вспомогательная геометрия исключена. `make_spherical_contacts.py` генерирует такой вариант **только в приватном каталоге**; 2/2 теста проходят. Дерево тел, 27 координат, 26 скоростей, 20 актуаторов и 1.8048682 кг сохранены. **Оригинальная контактная физика/проскальзывание при этом не сохраняются и не проверены.**
5. Запущен настоящий *один горизонт* IDTO (500 мс, 10 узлов) с сохранённого шестиопорного положения PR #40, при этом **начальная скорость заменена нулём для smoke-проверки**. Контрольный эксперимент, меняющий только цель Y:

| Цель Y | Итераций | Вычисленное конечное смещение root Y относительно сохранённого старта | Пиковый рассчитанный момент актуатора | Остановка |
|---|---:|---:|---:|---|
| 0 мм (контроль) | 60 | **−0.432 мм** | 0.336 Н·м | max_iters |
| +20 мм | 10 | **+4.062 мм** | 0.369 Н·м | max_iters |
| +20 мм | 60 | **+4.071 мм** | 0.371 Н·м | max_iters |

Результат — **оптимальная кандидатная траектория при выбранных приближённых параметрах и ограниченном числе итераций**. Статус `Maximum iterations reached` нельзя считать строгой сходимостью к оптимуму; это не свободное физическое выполнение этой траектории, а численный результат оптимизатора. 20 мм не достигнуты.

## Для воспроизведения

- Оригинальный Freenove CAD30 MJCF/STL и полный сохранённый `qpos/qvel` доступны только из личного архива (ссылки — в Issues/PR #40 и #50). Выполнить `convert_stl_to_obj.py` из `experiments/cad30/drake_bridge/` для временной конверсии оригинальных STL в OBJ для Drake 1.30. Никакие CAD-меши не коммитить.
- Применить `make_spherical_contacts.py` к приватной *копии* MJCF/OBJ:

```sh
PYTHONPATH=/private/CAD30-root python make_spherical_contacts.py \
  --original-mjcf /private/CAD30-root/source/mjcf/scene_local30_nominal.xml \
  --drake-converted-dir /private/CAD30-drake-obj \
  --output-dir /private/CAD30-idto-contact-proxy \
  --radius-mm 4
```

- Скопировать `cad30.cc`, `cad30.yaml`, `CMakeLists.txt` в `examples/cad30/` исходного IDTO. Добавить `add_subdirectory(cad30)` в IDTO `examples/CMakeLists.txt`. При несовместимом системном Eigen применить исключительно диагностический `patch -p1 < diag_format_compat.patch` в корне исходников IDTO.
- Использовать проверенную версию IDTO SHA выше, Drake 1.30.0, тот же изолированный Jammy sysroot; **линкеру нужен** `LIBRARY_PATH=$SYSROOT/usr/lib/x86_64-linux-gnu:$LIBRARY_PATH`. Сборка экспериментально завершена командой `cmake --build build --target cad30_idto_smoke -j1`.
- В окружении запуска задать библиотечные пути Drake/Jammy и `CAD30_DRAKE_MJCF=/private/CAD30-idto-contact-proxy/mjcf/scene_local30_nominal.xml`.
- `cad30_idto_smoke --test` принудительно сокращает решение до 10 итераций; без `--test` используется `max_iters: 60` из `cad30.yaml`. `mpc: false`, никакой физический симулятор не выполняет найденную траекторию.
- Проверять stdout: `Maximum iterations reached`, `q[T]`, `Max actuated torque`, а не только exit-code. Отдельно сравнивать `q_init[5]` (исходный Y) и `q[T][5]` (терминальный Y). Для контроля 0 мм указывать ту же `q_nom_end[5]=q_init[5]`.

## Непройденные критерии

- **Контактная parity G0:** Drake игнорирует armature=0.002 кг·м² для части DOF, `frictionloss`, `solref/solimp`; модельные ограничения ±0.7 Н·м не перенесены как жёсткие effort-limit (из MJCF получены `inf`). Прокси-сферы — заведомо иная контактная геометрия.
- **Глобальная G1:** нет терминально периодического 4-step цикла с четырьмя отдельными liftoff/landing, гарантированными ≥3 опорами и положительным продвижением корпуса. Требуются постановка полного периода и ограничения/проверка истинных контактов.
- **Физическая G2:** нет полного replay через реально достижимые PD servo-команды в одном MuJoCo `MjData`; нет подтверждённых Fz, удержания минимум трёх опор, проскальзывания, четырёх шагов, трёх повторений или движения реального Freenove.

**Следующий обязательный этап:** адаптировать стандартную phase-constrained/contact-implicit оптимизацию для всего периода. Строгий `≥3 loaded supports`, периодичность, физическая достижимость и ограничения приводов не заменяются ни soft-cost IDTO, ни геометрическими прокси. Не запускать железо, не добавлять CAD/публичные архивы, `main` не менять, PR оставить draft.

Полные stdout/stderr, точные версии и checksums — в приватном Drive (ссылка в Issue #50). Машинный отчёт: `results/IDTO_CAD30_SMOKE_20261105.json`.
