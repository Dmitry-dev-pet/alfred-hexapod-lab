## Reproduction on a supported machine

Use the **actual upstream** dependencies and root commit. After installing the official `training/requirements.txt`, run from `training`:

```bash
python evaluate2.py --policy native ../firmware/src/policy/trained_weights.h \
  --seeds 8 --seed-start 51000 --seconds 15 --workers 4 \
  --output rider2-native-8seed.json

python evaluate2.py --policy linear \
  --seeds 8 --seed-start 51000 --seconds 15 --workers 4 \
  --output rider2-linear-8seed.json
```

Results on a supported MuJoCo 3.16 + Python 3.11 may differ numerically from this run; **do not assert bit-identical behavior across runtimes**.

## Scientific conclusion

Original RL **did run in closed loop**, not merely imported. It performed better than the upstream linear baseline on this sampled family of adverse conditions, especially sensor scaling, but it **does not implement autonomous foot placement**. A real quadruped locomotion study needs a separate environment such as upstream `luwu_mjlab` for Lite3 or Mini2S, with NVIDIA GPU and genuinely learned foot contacts. Keep existing CAD30 research isolated.
