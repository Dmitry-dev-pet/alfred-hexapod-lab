# EN01 CPU MuJoCo P0 — physical probe, 2026-11-08

This is the first actually executed physics trial for the **hand-built approximate** four-actuator NavBot EN01, not a CAD-accurate model, not a real robot, and not the upstream control program.

## Execution

- Python 3.13 + restored offline MuJoCo 3.14.0 from the owner's Drive bundle; local Linux x86-64 CPU, not GitHub Actions, not Mac runner.
- Model file `model_v0.xml`; 0.322 kg across five rigid-body geoms; four actuators; actual `mujoco.mj_step`.
- Each scenario simulated **6.000 s = 3000 physics steps**, 2 ms timestep, log sampled every 20 ms but ground contacts checked every 2 ms.
- Source pinned `fuwei007/Navbot-EN01@3139f2fb32b38d10611feb905e16f8aa012f2f2e`; model and controller separately authored.
- Original 2208-90KV vs TMCM-6210 motor SKU discrepancy unresolved. Wheel torque limit **0.03 Nm is assumed**, not validated. Servo rated/short stall envelopes in `MODEL_NOTES.md`.
- The initial wheel controller had the wrong feedback sign; stand/crouch/jump all failed. Corrected gain and velocity damping were tested by CPU sweep and then evaluated on four fixed scenarios below. **Tuning on this exact model is NOT independent validation.**

## Results (recomputed using corrected diagnostic controller)

| Scenario | Whole-body conclusion | Max abs body pitch | Torso-ground samples (2 ms each) | Max absolute body x |
| --- | --- | --- | --- | --- |
| stand 6 s | **PASS provisional**: torso not touching, tilt <0.35 rad, x <0.5 m | 0.1859 rad / 10.65° | 0 | 0.338 m |
| slow crouch 6 s | **PASS provisional**: torso not touching, tilt <0.35 rad, x <0.5 m | 0.3228 rad / 18.50° | 0 | 0.387 m |
| slow prep + impulsive extend | **FAIL**: fall after acceleration; no verified upward takeoff / stable landing | 1.5748 rad / 90.23° | 417 | 0.246 m |
| assumed fast jump sequence | **FAIL**: falls during prep; no valid takeoff / landing | 3.1416 rad / 180° | 1893 | 0.451 m |

**Important strict jump classification:** In failing jump modes the contact solver occasionally saw apparent no-floor-contact intervals, longest 0.038 s (slow prep) or 0.034 s (fast). These are **not valid jumps**: criteria require upright prelaunch, positive vertical COM speed at separation, sustained whole-body flight >=0.020 s, then 2 s of stable upright support. Neither jump mode passed. A naive "contact absent >20 ms" metric would be a **false positive**.

The trial also revealed root-x drift up to 0.338–0.387 m in the nominally stationary stand/crouch runs: these are not fixed-position control successes. Next controller should reduce position/velocity tracking error while preserving upright stability.
