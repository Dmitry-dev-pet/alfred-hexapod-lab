# EN01 v2 — original STEP four-bar reconstruction, 9 November 2026

This is a review-only research step on PR #99. It reconstructs planar linkage geometry and runs new CPU MuJoCo dynamics. It does not calibrate the robot, train a policy, establish a successful jump, or update the published player.

## Source and mechanical reconstruction

Original `fuwei007/Navbot-EN01@3139f2fb32b38d10611feb905e16f8aa012f2f2e`, `Hardware/RebotModel/OriginalRobotModel.stp`, 12,358,579 bytes; Git blob `9156683a0bb694c84dc541a3e26b5f6b08db1a41`, raw SHA-256 `4715cf940718af95872bd2a771fdde61de3376bb748936e2299f94fa76416947`. OpenCascade reads all 73 component occurrences. Each pivot is extracted from a cylindrical surface and corroborated by mating components on both mirrored legs. See `linkage_evidence.json` for source face indices and radii.

A = servo shaft/horn, B = thigh/calf knee, C = calf/rod pivot, D = fixed body/rod pivot, W = wheel axis. CAD XY is the sagittal plane; CAD Z is the parallel shaft direction.

The 0.000467-mm AB/DC difference is retained from source, not silently rounded into a parallelogram. Mirrored sagittal axes differ by at most 6.96e-12 mm. The source tire has outer cylindrical surface radius 18.5 mm and 13-mm width; its midplanes are CAD Z=-11.65/+75.65 mm, giving 87.3-mm center spacing. The earlier v1 used tire placement origins rather than midplanes.

The analytic circle-intersection solver rejects unreachable/singular configurations and preserves the source assembly branch. The MJCF has a free base, four motors, and passive knee/rod hinges. Two site-based MuJoCo connect constraints close the loops. Independent analytical/FK comparison passed 101 input poses between -0.22 and +0.65 rad. These angle limits are conservative diagnostic choices, not measured mechanical stops.

Servo encoder zero/direction is unresolved. The source firmware's height-to-position mapping cannot be relabelled as a known physical crouch until that mapping is calibrated. Here negative model q raises W relative to A; the diagnostic crouch uses -0.18 rad and jump extension +0.20 rad. This differs deliberately from the earlier rigid-leg surrogate, so these rollouts are not a controlled A/B performance comparison.

## Six actual physical rollouts

MuJoCo 3.14.0, CPU, 1-ms step, 6,000 steps and 300 saved frames per scenario. All contacts/forces and loop errors are evaluated every physical step. Each saved qpos is followed by mj_forward so poses and telemetry refer to the same state. The wheel controller is the old experimental PD family, not source firmware. Push is 0.3 N forward for 0.1 s at t=2; drive requests 0.10 m/s at t=1–4; fall starts at a 60-degree lateral tilt plus 25-mm drop. Tracking and self-righting are not established.

## Unresolved dynamics

- Total mass 0.322 kg is retained from v0 as an assumption: body 0.180; each thigh/calf/rod/wheel 0.009/0.013/0.002/0.047 kg. This redistribution is not derived from material densities. COM and inertia remain approximate.
- Hip torque ceiling 0.14709975 Nm uses the previous nominal STS3032 reference. Linear no-load derating is assumed; this experiment does not use 0.441-Nm stall torque as continuous output.
- Wheel torque remains an assumed 0.030 Nm; motor SKU, winding/current/voltage, losses and limits are unresolved. A firmware voltage command cannot be treated as measured Nm.
- Torsion-spring stiffness/preload are unknown and omitted. CAD includes spring-cover/anchor parts; no spring force is inferred from their shapes.
- Planar joint axes are source-derived, but lateral load planes, capsule collisions, friction and rigid tire contacts are simplified. Original CAD is visual geometry, not collision geometry; robot self-collision is disabled. The torso box remains a surrogate.
- Servo zero, encoder direction, assembly interference, backlash, loaded rolling radius and real safety remain unvalidated.

## Replay and verification

`linkage_export.py` independently recomputes body poses from all 1,800 saved qpos states. Maximum difference is zero. The existing replay pipeline packages six immutable review-only entries, preserves 59 prior entries, is idempotent, and rejects --publish. The new renderer is an adapter for the existing player shell and drives each original CAD component using recorded thigh/calf/rod/wheel body transforms. It no longer moves an entire leg as one rigid group. Original mesh is reused from the existing player asset `hexapod/en01-original-cad-v1/original-meshes.json` (SHA-256 `8b034155dc50bb6c4e94a55bfa4ebca7b1fb742f2f38fc5c6c9f158c0cae313b`), not copied into this PR.

Five focused tests passed, including original-axis correspondence, 101 closed-loop positions and independent MuJoCo FK, singular/source-hash rejection, and forged visual/model rejection. Actual Three.js r169 checks passed for all 73 part mappings, 705,588 vertex reconstructions and 16,200 body transforms; nominal reconstruction residual is zero. JavaScript syntax passes.

Browser visual QA is BLOCKED in this executor: installed Chromium exits at `process_singleton_posix.cc: socket() failed: Operation not permitted`. No WebGL, camera, Android touch or full visual pass is claimed. The live Site and its library are unchanged. Generated pages/data/raw traces are review artifacts; only code, specs, source evidence and compact receipts belong in this PR.

## Reproduce

Install Python-compatible CadQuery 2.7.0 and MuJoCo 3.14.0; numpy is required for runtime checks. From repository root:

```bash
python -m research.navbot_en01.linkage --step /path/to/pinned/OriginalRobotModel.stp --out research/navbot_en01/linkage_evidence.json
python -m research.navbot_en01.linkage_model
python -m unittest discover -s tests -p test_en01_fourbar.py -v
python scripts/replay_pipeline.py run experiments/replay-pipeline/en01-fourbar-v2-stand-20261109.json
```

The last command calculates/exports/packages in a disposable review checkout, never with --publish. Repeat for crouch, jump, push, drive and fall. For visual preview, reuse the hash-checked original mesh and existing player-shell/vendor assets from the viewer branch; this stacked research base does not contain that later visual asset. No workflow, new runner, GPU, main merge or hardware purchase is needed.

Next gate: obtain source-backed servo calibration, spring parameters and mass/actuator evidence, then tune balance under frozen assumptions and evaluate held-out perturbations. Do not promote these surrogate results into hardware success.
