# MicroDuck — BAM, люфты и повторные CPU-испытания, 2026-11-09

**63/63 эпизода прошли временный критерий конечной устойчивости:** 7 сценариев × 3 seed × 3 модели привода. Это результат малой выбранной серии, а не оценка аппаратной надёжности. Вариант BAM с люфтами после толчка смещается на **30,3–53,3 см**; действующий PASS допускает такое смещение.

| Вариант | Устойчив в конце | Пик результирующей силы контактов с полом | Пик момента |
|---|---:|---:|---:|
| XML position PD | 21/21 | 81,0 Н | 0,960 Н·м |
| BAM M6 | 21/21 | 81,7 Н | 1,021 Н·м |
| BAM M6 + люфты + выходной энкодер | 21/21 | 83,8 Н | 1,020 Н·м |

Конечное горизонтальное смещение, см; диапазон по трём seed:

| Сценарий | XML PD | BAM | BAM + люфты |
|---|---:|---:|---:|
| stand | 0,2–1,6 | 0,3–1,5 | 0,2–1,6 |
| sit | 9,5–19,7 | 19,5–35,6 | 11,3–22,7 |
| fold | 1,5–2,8 | 2,1–2,3 | 1,2–2,3 |
| roll180 | 13,6–16,6 | 8,7–12,4 | 10,7–12,9 |
| pitch180 | 14,2–18,7 | 7,4–9,8 | 11,5–12,9 |
| side90 | 20,6–23,7 | 17,3–19,8 | 18,8–22,1 |
| push | 27,5–30,9 | 41,2–58,4 | 30,3–53,3 |

Для переворотов смещение отсчитывается после подготовительного падения, для остальных — с запуска контроллера. Пики измерены на каждом шаге 5 мс, включая подготовительное падение. Это силы контактной модели MuJoCo, не измерения на физическом роботе. Нагрузки, работа приводов, путь и смещение записаны отдельно и **не получили аппаратного допуска**. Тепловая модель не проверялась.

## Протокол

- Официальная v8 `velstand.onnx`: 61 вход / 14 выходов, нулевые команды, 50 Гц, без переобучения и фильтрации действий. CPU MuJoCo 3.10.0, ONNX Runtime 1.24.4.
- По 6 секунд управления: 300 кадров, всего 18 900. Для трёх синтетических переворотов — ещё 0,6 секунды падения с удержанием суставов перед управлением. Новая серия: 78 840 физических шагов.
- Seed `20261109`, `20261110`, `20261111`: одинаковые рецепты во всех вариантах. Суставы ±0,02 рад, ориентация ±10°, XY ±1 см, высота сброса 17–19 см. `push` задаёт горизонтальную скорость 0,6–0,8 м/с после первой секунды; это не измеренная сила толчка.
- BAM XL330 M6: kp=200, без ограничителя тока, как в исходной тренировочной конфигурации. Напряжение 6,5–8,2 В, коэффициент просадки 0–0,2 по seed, нижняя граница напряжения 6 В.
- 14 пассивных суставов с люфтом ±1°. Позиция/скорость в наблюдениях = motor + passive. Обратная связь положения firmware = motor + passive; скорость для обратной ЭДС/трения остаётся motor-side. Семантика взята из upstream `BacklashEncoderBamActuator` и `tasks/backlash.py`; базовый CPU `PolicyInference` сам этот учёт ещё не выполняет.
- PASS: последняя непрерывная секунда имеет высоту 9–19 см, наклон ≤20°, скорость ≤0,25 м/с, угловую скорость ≤1 рад/с и контакт хотя бы одной стопы с полом; нет численных предупреждений/автоматического сброса. Исключения записываются как ERROR и сохраняют знаменатель.
- Сохранены qpos/qvel/ctrl, позиционные цели, подготовительные кадры, метрики и SHA-256 каждого эпизода. Коллизии `groundcontact`, а не полная `allcollisions`. Прочие тренировочные DR, шумы и задержки не включены. Три seed не обосновывают статистическую надёжность.

## Воспроизведение

Python 3.12; два архива исходников по immutable commit выше и официальный ONNX с проверкой SHA-256. Установить `requirements-bam-cpu.txt` в отдельное окружение. Из корня нашего репозитория:

```bash
python research/microduck/check_bam_backlash.py --rl-root /path/to/microduck_rl --policy /path/to/velstand.onnx
python research/microduck/bam_backlash_cpu.py --rl-root /path/to/microduck_rl --bam-root /path/to/bam --source-manifest research/microduck/bam_cpu_sources.json --policy /path/to/velstand.onnx --output-dir results/microduck-bam-v2
```
